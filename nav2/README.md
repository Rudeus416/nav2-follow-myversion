# 毫米波 Nav2 绕行跟随（ROS 2 Humble）

完整路径规划源码、插件接入、中文注释说明及独立编译方法见 [整车绕障代码说明](whole_body/README.md)。

启用后，人物测量生成跟随终点，或由网页选取固定终点。本项目 `whole_body/` 中的规划插件在位置与朝向空间搜索，完整车身及转弯扫掠都不能碰到障碍、手绘禁区或启用的紫色缓冲；DWB 用同一碰撞规则筛选执行速度。固定选点执行通过复核的预览路径，人物跟随保留目标更新和丢失停车门控。

速度链路：`controller_server → /visual_car/nav2_cmd_vel → control.py 强停/新鲜度/速度限制 → /cmd_vel → Ranger`。只有视觉控制向底盘发送速度。手动模式保持原来的人工控制，不经过 Nav2 绕行；此功能不包含独立 Collision Monitor。

## 安装与安装参数

本机已检查到 Nav2 1.1.20（ROS 2 Humble）所需包。换到未安装的运行机器时执行：

```bash
sudo apt-get update
sudo apt-get install ros-humble-navigation2 ros-humble-nav2-bringup
```

当前按旧控制逻辑和已保存标定，采用以下二维配置：

1. 两个 costmap 的 `footprint` 为前后长 0.494 m、左右宽 0.364 m，假设 `base_link` 位于矩形中心，顶点 `(±0.247, ±0.182)` m，额外边距 0.05 m。尺寸按用户指定的轴距、轮距设置；紫色禁入半径默认 0 m，可在网页设为 0～1.5 m，Nav2 规划及导航输出上限 0.18 m/s、0.4 rad/s。
2. 启动文件读取 `data/data_transfer/20260920_160622_946624.json`，忽略其中的高度、俯仰和横滚，将雷达—相机平面变换与相机—底盘平面位姿组合，发布 `base_link → ti_mmwave_0`。默认结果为 x=-0.02 m、y=0.02 m、yaw=-2.8°（约 -0.0488692 rad），z/roll/pitch=0。**这是根据保存标定和旧控制假设推导的二维 TF，不是历史实车 TF 测量记录。** 若已有其他节点发布雷达 TF，设置 `NAV2_PUBLISH_RADAR_TF=false`，避免同一子坐标系出现多个父节点。
3. `NAV2_CAMERA_X`、`NAV2_CAMERA_Y`、`NAV2_CAMERA_YAW` 默认均为 0。旧 PID 跟随直接使用相机距离和方位，没有安装偏移补偿；现在用零值显式沿用这一假设，并非找到过实测零外参。可按实际测量覆盖，单位米、米、弧度，雷达 TF 会同步组合相机偏移。历史 `camera_height_m=0.5` 仍只是原来的测距参数，不用于本二维 TF。
4. 雷达话题 `/ti_mmwave/radar_scan_pcl`，PointCloud2 坐标系 `ti_mmwave_0`（原始 ADC 的 `radar` 不适用）。沿用跟随的 3TX profile、200 ms 帧周期和 5 m 距离上限。代价地图高度过滤上下限暂放宽到 ±1000000 m，层级上限同步放宽，使实际雷达点不会因高度阈值被排除；这是暂不考虑高度的工程设置，不是历史参数。没有改写原始点云 Z，范围判断仍可能受 Z 影响，也不做地面点剔除。

`NAV2_RADAR_CALIBRATION` 可指定 `data/data_transfer` 下其他 V2、`radar_ros` 标定文件名。Nav2 模式同时预载该文件用于原有图像投影、人物测距；这些功能仍使用完整三维标定。预载不会自动启动雷达。若传感器相对安装已改变，需重新标定。

修改话题时同步修改两个 costmap 的 `radar.topic` 和 `NAV2_RADAR_TOPIC`；修改坐标系时同步修改两个 costmap 的 `radar.sensor_frame` 和 `NAV2_RADAR_FRAME`。底盘轮廓覆盖范围、实际传感器安装位姿与高度过滤仍需后续实测核对。

### 停车预览与停止原因

运动控制面板显示当前控制状态，包括强停、未开始跟随、人物 ID 未检测到、跟踪或距离超时、雷达超时、导航目标等待接受和速度等待等。显示的是软件控制条件，不代表底盘已经执行了指令。

保持强制停止，选定当前可见的人物 ID（雷达或叠加模式需启用雷达）；距离测量有效后，点击“人物追踪”中的“记录人物点并规划”。此按钮只请求 `ComputePathToPose` 规划，不调用导航执行动作、不解除强停、不发送速度。无需点击“开始跟随”。成功返回青色虚线，失败显示规划状态/错误码，超过 5 秒未返回则取消；预览为一次性的场景快照，30 秒后隐藏，需重新点击计算。地图缺失或过期时不会绘制预览。

停车预览的目标跟踪和距离/方位测量使用独立的 **2 秒**有效期，按钮下方显示实际数据延迟；超过 2 秒或目标不可见时仍拒绝预览。此有效期只用于强停状态下的路径预览，不改变自动跟随的运动超时限制。

目标已在跟随距离内时提示无需前进。更改配置、切换模式或强停状态会清除旧预览。若识别到了人物但无法预览，请根据按钮下方的目标/距离超时提示、TF 错误或 Nav2 规划错误继续排查。

在项目根目录操作。先在网页强停，然后停止旧服务：

```bash
./run.sh stop
```

<a id="startup-commands"></a>

**所有启动项指令放这里**

首次部署或更新整车插件源码后先编译（不启动车辆）：

```bash
bash nav2/whole_body/build.sh
```

构建脚本会在独立子进程隔离 Conda 环境，使用系统 ROS/C++/Python 和 `fmt`、`spdlog`，重建本项目 CMake 配置缓存；不会改变当前终端或视觉服务环境。若此前遇到 `GLIBCXX_3.4.30 not found`，更新脚本后直接重新执行上述命令，全部测试与安装通过后再启动。无需替换系统或 Conda 的库文件。

使用地图或叠加模式时，先将小车放到下文指定起点。以下启动命令**只选一条执行**，切换启动方式前先强停并停止旧服务。

**视觉障碍检测默认关闭（不带 `NAV2_VISION_OBSTACLES=1`）：**

```bash
# 只使用毫米波障碍层
NAV2_ENABLED=1 NAV2_OBSTACLE_MODE=radar ./run.sh start

# 只使用手绘静态地图，不要求毫米波点云
NAV2_ENABLED=1 NAV2_OBSTACLE_MODE=map ./run.sh start

# 静态地图与毫米波障碍层叠加
NAV2_ENABLED=1 NAV2_OBSTACLE_MODE=both ./run.sh start
```

**视觉障碍检测启动时开启：**

```bash
# 毫米波 + 视觉障碍检测
NAV2_ENABLED=1 NAV2_OBSTACLE_MODE=radar NAV2_VISION_OBSTACLES=1 ./run.sh start

# 手绘静态地图 + 视觉障碍检测
NAV2_ENABLED=1 NAV2_OBSTACLE_MODE=map NAV2_VISION_OBSTACLES=1 ./run.sh start

# 静态地图 + 毫米波 + 视觉障碍检测
NAV2_ENABLED=1 NAV2_OBSTACLE_MODE=both NAV2_VISION_OBSTACLES=1 ./run.sh start
```

启动后可先强停，再在网页勾选或取消“启用视觉障碍检测（参与导航避障）”，无需重启。网页选择仅对本次运行生效；“前方疑似障碍预览”只控制图像显示，不开启导航视觉避障。若终端已导出 `NAV2_VISION_OBSTACLES=1`，省略变量会继承该值，应在所选命令中显式设置 `NAV2_VISION_OBSTACLES=0` 才能关闭。

**Nav2 深度推理尺寸（R39）：**按本次选择，视觉避障开启时默认为 **512 上限**，即实际请求为 `min(原 depth_imgsz, 512)`。相机原图和人物分割输入尺寸不变；只为新深度任务生成参数副本，不写回原配置。关闭视觉避障或退出 Nav2 后，新任务恢复原尺寸；已排队/正在推理的任务保留原值。

```bash
# 手绘静态地图 + 视觉避障；显式使用 512（与当前默认一致）
NAV2_ENABLED=1 NAV2_OBSTACLE_MODE=map NAV2_VISION_OBSTACLES=1 NAV2_DEPTH_IMGSZ=512 ./run.sh start

# 可选：改为 640；更重视深度细节时再调整
NAV2_ENABLED=1 NAV2_OBSTACLE_MODE=map NAV2_VISION_OBSTACLES=1 NAV2_DEPTH_IMGSZ=640 ./run.sh start

# 可选：保持原配置的深度尺寸（原配置允许的最大值为 1280，不再额外缩小）
NAV2_ENABLED=1 NAV2_OBSTACLE_MODE=map NAV2_VISION_OBSTACLES=1 NAV2_DEPTH_IMGSZ=1280 ./run.sh start
```

以上命令任选一条；更改此启动参数需先停车并执行 `./run.sh stop`。`NAV2_DEPTH_IMGSZ` 接受 320～1280 的 32 倍数整数，非法值在安装接入前拒绝。启动后的首个适配任务会在 `control.log` 显示 `Nav2 深度推理尺寸：768 → 512`；“视觉新帧首次消费”中的 `depth_imgsz` 是该结果实际请求的尺寸，不能只看原配置页仍显示的 768。只读 `/api/nav2/vision-enabled` 的 `depth_profile` 提供实际档位、是否安装和应用错误。

降低输入可能减少细小障碍的深度细节，也会影响复用同帧深度的人物测距结果；模型仍会输出原图大小的深度图，因此并未减少该输出的传输量。此改动用于减轻推理负载，不保证消除所有延迟尖峰；1.2 秒零速与 2 秒取消的保护继续生效。需在同一场景复测深度时延和障碍检出。原因和文件范围见 [R39 修复记录](PERFORMANCE_REPORT.md#r39)。

**Nav2 独立 YOLOE 物体分割：**视觉障碍开启时默认启用，原人物跟踪不变。默认独立 CPU 进程、最多 2 Hz；首次加载需等待，失败或超时会显示状态并保留深度障碍检查。

```bash
# 手绘地图 + 视觉深度 + 独立 YOLOE（显式开启，与默认一致）
NAV2_ENABLED=1 NAV2_OBSTACLE_MODE=map NAV2_VISION_OBSTACLES=1 NAV2_VISION_YOLO=1 ./run.sh start

# 仅关闭新增 YOLOE，仍使用视觉深度障碍
NAV2_ENABLED=1 NAV2_OBSTACLE_MODE=map NAV2_VISION_OBSTACLES=1 NAV2_VISION_YOLO=0 ./run.sh start
```

**不使用 Nav2，使用原跟随模式：**

```bash
NAV2_ENABLED=0 ./run.sh start
```

网页避障地图显示当前障碍来源，显示的代价地图包含所选图层。切换模式需要重启，不支持行驶中切换。雷达模式和叠加模式仍需启用毫米波；地图模式下毫米波不参与 Nav2 障碍判断，但网页独立的雷达测距开关仍可影响人物测距。

地图默认为 `nav2/maps/corridor.yaml`，对应净宽 2.1 米、长 8.4 米的新走廊地图（长度由 4.2 米翻倍，44×168 像素，0.05 米/像素；沿地图 +Y 延长，起点不变），可通过 `NAV2_MAP_FILE` 指定其它地图，但当前起点对齐固定为本走廊的设定。启动前将小车 base_link 放在最下排三块完整砖的中间砖中心（地图 x=1.2、y=0.3），车头朝上。底盘里程计必须从零开始；程序发布固定 `map → odom`：平移 (1.2,0.3)，旋转 +90°。不要同时运行 AMCL、SLAM 或其它发布同一变换的节点。当前仅靠轮式里程计维持位置，漂移不自动修正；每次重启重新对齐起点。

静态地图两侧墙、两端开放，未描述图外环境；滚动代价地图的图外区域不应视为已验证通行区域。先保持强停测试路径。仅地图模式无法检测临时障碍物，人物跟随仍需有效视觉测量。叠加模式保留雷达障碍，因此不会掩盖雷达误检。

启动后打开 http://192.168.31.214:8890/ 并刷新页面，确认“障碍来源”与选择一致。保持强停，选择当前人物 ID，再点击“记录人物点并规划”；雷达或叠加模式需先启用雷达。

常用管理命令：

```bash
./run.sh status
./run.sh logs nav2
./run.sh stop
```

每次启动都需带上 `NAV2_ENABLED=1` 和所选 `NAV2_OBSTACLE_MODE`；不指定障碍模式默认使用雷达，不启用 Nav2 时仍走原来的跟随模式。


脚本会检查依赖，启用 Ranger 的 `odom → base_link` TF，管理 Nav2 生命周期，再启动视觉控制。Nav2 激活失败不会启动视觉控制。启用状态随本次启动生效，重启时也需带 `NAV2_ENABLED=1`；不带时保留原来的 PID 跟随。

页面保持强制停止状态，雷达或叠加模式先启用现有毫米波雷达（或启动外部驱动），确认上述 TF 和轮廓，再解除强停、开始跟随。雷达点云超过 0.6 s、里程计 TF 超过 0.5 s、Nav2 速度超过 0.3 s 或视觉目标超时，自动跟随输出零速度。异步接受的旧导航目标也会取消。网页模式栏和 `/api/status` 会显示 Nav2 状态及错误。`NAV2_PARAMS=/绝对路径/params.yaml` 可使用自定义配置。

## 适用范围与验证

默认雷达模式是无预建地图、基于局部观测的绕行方案；地图及叠加模式使用手绘静态地图。当前均不使用 AMCL 或 SLAM。毫米波点云稀疏且视场有限，未检测到回波不能证明空间可通行；这里将未观测栅格作为自由空间，才能在无地图条件下规划。默认启用点云射线清障，漏检可能清除障碍；没有被射线扫过的旧障碍可能残留并阻止规划。应先在隔离场地低速检查雷达静态障碍检测、代价地图及路径；不能据此承诺全方位防碰撞。目标人物自身也会保留在障碍地图中，不会从点云里删除。

离线回归覆盖目标几何、跟随距离、目标更新边界、速度超时、传感器失效和强停后晚到的 action 响应；尚未完成 Nav2 运行时与实车绕行验证。首次实车验证需确认目标丢失停车、雷达断流停车、强停，以及正面障碍的左右绕行行为。

参考：[Nav2 Humble 参数](https://github.com/ros-navigation/navigation2/blob/humble/nav2_bringup/params/nav2_params.yaml)。

## 启动错误：RecoveryNode 未识别

Humble 会初始化单目标和多目标两个导航器。启动文件现在分别指定 `follow.xml` 和 `follow_through_poses.xml`，并加载两种规划动作插件，避免回退到依赖恢复节点的系统默认多目标行为树。当前不启用自动旋转、倒车等恢复行为，规划或跟随失败时任务结束。

修改后按上述启动步骤停止旧服务，再以所选模式启动。页面启动后保持强停，雷达或叠加模式启用雷达；代价地图在接收到有效点云前仍会提示 observation buffer 超时，这与行为树加载失败是不同问题。

### Nav2 自动跟随的视觉时效

以下人物新鲜度与目标更新规则针对原实时跟随入口；明确点击执行的锁定段按后文“人物路线旁的开始追踪”和 R31 规则处理。

Nav2 接入单独使用 1.2 秒的目标测量有效期（按原图采集时间计算），发送目标、速度放行和页面诊断使用同一阈值，避免沿用 0.6 秒阈值导致反复取消。Nav2 输出另限幅为前进 0.18 m/s、倒退 0.15 m/s、角速度 ±0.4 rad/s；页面设置可进一步降低上限。普通视觉跟随仍使用原来的超时规则，停车预览仍为 2 秒。目标消失、距离缺失或超时仍停车，雷达、TF 和导航速度的新鲜度检查保持不变。该调整需重启服务生效，不能修正测距错误或保证规划成功。

### 导航目标防抖

仅在 Nav2 接入中对 odom 目标进行确认：连续 3 次测量的位置两两相距不超过 0.35 米、时间跨度至少 0.2 秒，才采用平均位置；相邻测量间隔超过 1.2 秒则重新确认。单帧跳变不替换正在执行的目标。已执行目标偏移超过 0.5 米且距上次发送至少 2 秒，才取消并重新确认新目标。强停、目标消失、进入跟随距离或传感器失效仍沿用停车逻辑，并清除防抖历史。停车预览保持原有单次规划行为。此功能减少目标抖动引起的任务切换，不会冻结 Nav2 根据障碍地图进行的正常重规划，也不能消除超时造成的取消。

导航实际停止或取消时，接入层会记录第一次触发原因，重复停车检查不会覆盖它或持续刷日志。避障地图区域显示“最近一次导航停止”及距今时间；详细记录位于 `data/runtime/control.log`，搜索 `Nav2 停止/取消`（接入层运行在控制进程，因此不写入 nav2.log）。可区分目标丢失、测量超时、用户/配置重置、稳定目标更新以及雷达/TF 等异常。历史停止原因不代表当前仍有该故障。

### 人物短暂超时的停车等待

Nav2 模式下，人物数据超过 1.2 秒仍立即输出零速度，但在测量年龄不超过 2.0 秒时短暂保留导航任务，最多额外等待 0.8 秒。恢复到 1.2 秒以内后，使用新的 Nav2 速度继续；等待期间清除速度缓存，不沿用暂停前指令。超过 2.0 秒仍取消，截止时间按原始测量时间计算，重复检查不会延长。目标丢失、距离缺失、强停及雷达/TF 异常仍取消。该机制减少短暂超时造成的任务重启，不修复视觉计算延迟，也不能消除规划失败；普通跟随与停车预览规则不变。

### 网页地图、车位与预计路线

网页“地图与导航路线”区域优先显示 `/map` 静态底图，并叠加局部代价地图；没有静态地图时使用原滚动障碍地图。静态底图按地图方向朝上显示。蓝色箭头表示 `odom → base_link` 给出的当前位置与朝向，蓝框为车身，绿色实线为导航规划路线，青色虚线为停车预览路线。全部图层先对齐到 odom，再统一绘制；静态地图不会因只发布一次而在 3 秒后过期。实时车位和导航路径仍保留过期检查，避免把旧数据当作当前状态。

需要重启服务并刷新网页。车位是里程计估计，不是新增的绝对定位；规划路线需要先请求停车预览或启动导航，不会仅因加载地图自动生成。

## 网页添加阻挡区与膨胀范围

局部、全局代价地图均使用本项目 `visual_car_nav2::HardBuffer`。默认半径 **0 米**；开启且半径大于 0 时，把障碍周围栅格标为紫色禁区。规划及执行都要求**带 padding 的整个车身不接触紫色区**，不是只要求车身中心避开。关闭或设为 0 时不产生紫色缓冲，但完整车身仍须避开障碍、手绘禁区及边界。车身轮廓和 `footprint_padding=0.05` 不变；不再保留旧版 0.60 米基础膨胀层。

以 `map` 或 `both` 模式启动后，网页“地图与导航路线”下方提供阻挡区编辑：

1. 保持网页强制停止，等待静态地图出现。
2. 点击“绘制阻挡区”，在地图上用鼠标或手机手指拖出矩形。
3. 检查虚线框位置，点击“应用阻挡区”。黑色矩形会合并到 Nav2 使用的静态地图中，而不只是页面装饰。
4. 等待代价地图更新，再重新点击“记录人物点并规划”，检查路线是否绕开新增区域。
5. “取消框选”放弃未应用的矩形；“撤销上一块”删除最后一个新增区域；“清空新增区域”删除全部网页新增区域，原地图墙体保持不变。

新增矩形按地图栅格对齐，当前地图为每格 0.05 米，最多 200 个。编辑时后端也检查强停状态；雷达单独模式不开放此功能。应用后旧停车预览会清除，不会自动开始运动。

保存位置为 `data/nav2_map_edits/<底图指纹>.json`，与原始 PGM/YAML 分开。地图内容、尺寸或原点变化会使用独立的编辑记录；同一底图重启后自动恢复。Nav2 启动时由 `nav2_map_publisher.py` 读取 `/map` 并发布合成地图 `/visual_car/edited_map`，两个代价地图的静态层订阅后者。网页保存后通知该节点重新加载；运行故障可在 `data/runtime/nav2.log` 中查询。没有新增阻挡区时合成地图与原图一致。叠加模式仍会保留雷达障碍。

代码更新后需要停止并重新启动服务，再刷新网页。此功能未替代定位或雷达检测，不会修正人物测距、视觉超时或里程计漂移。


### 自由画笔（鼠标／手机手指）

在地图或叠加模式保持强停，选择“自由画笔”和笔宽，点击“绘制阻挡区”后按住拖动画线。选择“矩形”可继续使用原矩形工具。笔宽为 1、3、5 个地图栅格，当前 0.05 米分辨率对应 5、15、25 厘米。连续移动会自动补齐中间笔迹。每笔绘画完成后点击“应用阻挡区”，再画下一笔；“撤销上一块”可整笔撤销，“取消框选”放弃未应用笔迹。自由画笔只标记涂过的区域，闭合线不会自动填满内部。新增笔迹与矩形统一保存、参与规划并支持重启恢复，旧矩形记录继续兼容。

这是对现有底图添加障碍的工具，并非 SLAM 或自动测量；地图比例和实际障碍位置仍需核对。当前不支持在网页改变地图尺寸、擦除原始墙体或重设定位。更新后重启服务并刷新网页。

## 独立禁入区相机预览（停车对齐）

自有导航面板的“红黄虚拟墙 · 停车预览”中提供“显示红色禁区墙”开关。地图／叠加模式下保持强停，勾选后显示独立相机窗口；窄屏下排列在地图下方。仅将已应用的网页手绘禁入区域边界投影成淡红色墙面，不改变原相机画面、检测结果或导航地图。取消勾选停止请求；约每秒更新一次，图片独立缩放到最多 960 像素宽。

可设置相机高度、向下俯角和虚拟墙高度。默认分别为 0.5 米、0 度、0.8 米，属于待核对的显示参数；平面安装位置及偏航沿用 Nav2 相机安装参数，横滚暂按 0。需在停车状态核对地图起点、实际安装参数和显示位置。普通跟随和原相机功能不依赖此接口。

这不是新增的障碍检测或精确增强现实定位。相机画面和里程计未做严格同帧同步，因此当前只开放强停预览，解除强停后暂停，TF 或图像缺失时显示原因。使用当前相机标定文件投影，不支持任意更换镜头后的未标定画面。改动需重启服务、刷新页面生效。

## 固定路线：第一阶段停车校验

地图／叠加模式下保持强停，点击“选取路线终点”，在地图空地点击，再点击“预览选点路线”。不需要选定人物 ID。后端验证地图版本、边界及目标栅格；最终由 Nav2 判断路线是否可行。显示的是停车规划预览，不发送导航执行动作。地图编辑后应重新选点；规划成功不表示已确认执行路线。

可在自有导航面板的预览画面区域勾选“显示疑似障碍预览”（原“前方疑似障碍预览”）。独立窗口只读使用已有深度结果及同帧相机图像，不改变原相机、跟踪和控制流程。按填写的相机高度、向下俯角及深度比例，筛选相机前方约 0.15～3 米、左右各 0.6 米、估计离地 0.12～1.8 米的连通区域，以橙色显示候选区域和估计前向距离。未做物体类别识别，不覆盖低矮、悬空、透明物体或视野外障碍；这些范围相对于相机而非经过确认的底盘扫掠空间。

默认深度比例 1 尚未校验，相机横滚假设为 0。先在停车状态把已知距离的物体放入画面，核对标注、距离与安装参数。图像年龄超过 1.2 秒会拒绝预览；无候选区域不代表通道安全。当前没有固定路线执行或“检测到障碍自动停车”的控制接入，下一阶段需在完成现场校验后实现，原有人物丢失停车规则不变。

## 可选视觉障碍层（实验功能，默认关闭）

现在可将相机深度估计的疑似障碍加入 Nav2 局部、全局代价地图，与手绘禁入区一起参与规划。启动命令统一见[所有启动项指令](#startup-commands)，选择对应的“视觉障碍检测启动时开启”命令。

也可与 `both` 或 `radar` 模式组合。省略 `NAV2_VISION_OBSTACLES=1` 则关闭，保持原有行为。网页显示视觉障碍层是否启用、数据年龄、候选点数量和异常；原“前方疑似障碍预览”开关仍只管显示，不会开启或关闭控制保护。

安装参数通过启动环境变量设置：`NAV2_VISION_HEIGHT`（米，默认 0.5）、`NAV2_VISION_PITCH`（向下俯角，度，默认 0）、`NAV2_VISION_SCALE`（深度比例，默认 1）。平面安装参数沿用 `NAV2_CAMERA_X/Y/YAW`，横滚暂按 0。网页预览输入不会修改这些控制参数。必须先停车对照实物核对距离和位置，不能把默认参数当作准确标定。

接入层只读已有深度结果，不改变原人物跟踪或相机推理。按图像时间查找底盘 TF，在相机前方 0.1～4 米、左右各 2 米、估计离地 0.1～1.8 米范围内筛选连通候选区域。每个区域至少包含 6 个采样像素，按前向距离的第 10 百分位选取最近的一个区域，转换为 odom 栅格，通过 `/visual_car/vision_costmap` 发布。每次有效新帧替换视觉候选，不再保留旧候选两秒。连通区域不等同于物体类别，相连的多个物体可能成为一个区域，目标人物也可能被选中；独立橙色预览窗口仍显示其自身范围内的候选。

地图及叠加模式下，视觉栅格同时合入 `/visual_car/edited_map` 中的原地图墙体和手绘阻挡区，静态层显式启用最大代价合并，避免视觉自由栅格覆盖墙体。墙体按栅格面积转换，保留旋转坐标下的薄墙；未收到静态地图时拒绝发布视觉栅格并保持导航停止。仅雷达模式不等待静态地图。这些修改需重启服务生效。

有效像素不足、源深度超过 1.2 秒或 TF 失败时禁止 Nav2 输出并取消任务。底盘前方 0.7 米以内且左右各 0.4 米通道内出现候选时立即停止导航；更远的障碍交给规划器及局部控制器决定绕行，无可行路径则失败停止。该检查只保护 Nav2 自动速度，手动控制维持原逻辑。近距障碍消失、数据恢复后，开启着的人物跟随可能重新规划；如需保持停车请使用强停。

这不是经过验证的安全防碰撞功能：单目尺度误差、地面筛选、透明/低矮物体、视野盲区和安装误差均可能造成漏检或误检。不能承诺任意障碍必停。小地图代价区域是估计结果。此次仅把视觉层接入已有 Nav2 导航，固定选点仍为停车预览，未新增固定路线执行按钮，也未允许目标遮挡后沿旧路径继续走。


## 单地图模式的四周禁区

`NAV2_OBSTACLE_MODE=map` 自动启用独立边界层 `/visual_car/map_boundary`：在原地图外侧紧贴四条边添加一格宽、代价 100 的连续禁区，封闭四条边（包括原来开放的两端）。原地图文件、内部空间和起点不变；仅独立边界栅格宽高各增加两格、原点沿地图轴各向外移一格，正确处理旋转。当前边线宽 5 厘米，紫色膨胀区另行计算。局部和全局代价地图均在视觉层之前合入边界；最后的视觉层同时保留静态墙体和边界，随后计算膨胀；网页代价图仍裁剪到原地图范围，图外红边可能不显示，向内的膨胀区域仍显示。无需重新绘制，清除手绘区域不会移除边界。`radar` 和 `both` 模式不启用此边界。

重启后先保持强停，确认四周红色边界和小车位置，再计算停车预览路径；地图内无路可走时应规划失败，不能再从地图两端绕到外侧。车辆起始位置须与地图设置一致；此约束基于里程计定位，不能修正定位漂移，也不限制原手动控制。边界附近可能因车身轮廓和安全间距而无法规划，不能以缩小车身轮廓解决。


视觉层在地图及叠加模式下先按静态地图范围过滤候选，再选择地图内最近的有效连通区域，地图外候选不写入视觉障碍栅格。网页的 Nav2 代价叠加也裁剪到静态地图边缘，隐藏图外膨胀区域。近距停车仍检查全部有效候选，不因显示裁剪忽略车前危险。若障碍深度、高度或连通面积不满足筛选条件，仍可能没有标记；此功能不是物体类别识别。


地图模式启动先由 `nav2/map_startup.py` 在 45 秒期限内配置、激活地图，并确认原图、编辑地图和所需边界图已发布，然后启动导航生命周期管理器。状态切换响应丢失时查询实际状态，不重复发送同一切换；失败则结束本次 Nav2 启动，记录缺失图层。此处理避免地图服务响应丢失无限阻塞后续启动，不代表已修复底层 DDS 通信异常。


虚拟墙相机窗口按变化生成停车快照：首次勾选、保存/撤销/清除手绘区域、调整投影参数或车位累计变化至少 1 厘米/1 度时更新。静止且墙体未变时保留旧快照，不再每秒请求图像；背景人物变化也不会刷新。解除强停或位姿失效时隐藏，重新强停且数据有效后更新。未保存的绘制草稿不生成虚拟墙。请求失败可重新勾选重试。

“前方疑似障碍预览”勾选框仅开关独立橙色相机预览，不执行路线，也不启停导航视觉障碍层；该层仍由 `NAV2_VISION_OBSTACLES=1` 开启。“选取终点”及“预览选点路线”是另一组停车规划功能。


视觉障碍合并顺序：静态层 → 边界层（单地图模式）→ 视觉合成层 → 膨胀层。视觉合成层包含地图内最近有效候选、原墙体、手绘阻挡区及单地图模式的四周边界，避免最后再叠加只有边界的地图而丢失视觉障碍。需重启 Nav2 和视觉服务；候选仍取决于单目深度及安装参数，不能凭候选数量确认实物标注正确。

停车路径规划失败、超时或返回空路径时，地图下方显示红色“无有效路径”及失败原因。重新计算、清除或成功获得路径后撤销提示；尚未规划不等同于规划失败。


## 以所选人物为目标执行导航

人物自动跟随已接入 NavigateToPose，和手动选点停车预览是两条独立流程。启用 Nav2 后，选择画面中可见的人物 ID，在运动控制区启用自动跟随并解除强停；仅选择 ID、检测到人物或点击停车预览不会启动小车。

接入层使用所选人物的同帧距离和方位生成 odom 导航目标，终点位于人物前方的跟随距离处，而不是人物脚下；远目标分段推进，单次目标最远 3 米。通过连续 3 帧的位置稳定检查后发送目标，Nav2 自动规划并执行。人物位置稳定移动超过阈值时更新目标；无可行路径不能执行。人物丢失、距离缺失、传感器异常或强停时停车，短暂数据过期期间也不输出运动速度。

测试地图及视觉避障：使用[所有启动项指令](#startup-commands)中的“手绘静态地图 + 视觉障碍检测”。先确认人物 ID、距离、车位与地图一致，再启用跟随；若不动，查看控制状态和 Nav2 错误，不需要点击“预览选点路线”来执行人物跟随。


## 网页切换视觉障碍检测

**不带 `NAV2_VISION_OBSTACLES=1` 时，视觉障碍检测默认关闭。** 完整启动命令统一见[所有启动项指令](#startup-commands)。

“导航避障与紫色缓冲”中的“启用视觉障碍检测（参与导航避障）”可在强停状态切换，同时更新局部和全局视觉图层。关闭后不再处理视觉候选，导航不再使用该层，静态墙体及禁区保留；开启后等待新的有效深度数据。切换不解除强停、不启动跟随。“前方疑似障碍预览”仍仅控制独立图像显示。

更新代码后需重启一次加载可切换图层；此后无需重启即可勾选。`NAV2_VISION_OBSTACLES=1` 设置启动默认开启，不填写则默认关闭；网页选择仅对本次运行生效。切换失败时保持强停，重新切换成功或重启后再使用。


### 视觉障碍黄色虚拟墙

开启“启用视觉障碍检测”后，在强停状态可勾选其下方“显示视觉障碍黄色虚拟墙”。在原红色虚拟墙相机窗口中，将实际选中的视觉候选栅格叠加为半透明黄色墙，不新增相机窗口。红墙和黄墙可独立勾选，也可同时显示。黄色墙使用导航视觉层的相机高度及俯角，示意墙高 0.8 米，不代表物体真实高度。候选区域或车位变化才重新生成；数据过期、候选消失、关闭视觉检测或解除强停时隐藏。该勾选只控制显示，不改变障碍筛选或运动控制。更新后重启服务并刷新网页。


地图接口超时排查：已修复新增视觉定时器反向获取引擎锁与导航锁的死锁风险；先复制引擎记录并释放引擎锁，再进入导航临界区。网页请求失败时仅保留带“缓存底图”标识的静态背景，隐藏车位、路径、动态障碍及虚拟墙，禁用地图操作；连接恢复后自动恢复实时显示。若旧进程已死锁，需停车后重启服务加载修复。


红黄墙合并预览修复：清除手绘区域仅改变红墙，黄色墙仍来自视觉候选。勾选黄墙后不会因一次视觉状态采样暂时失效而静默改成只请求红墙；数据过期时隐藏并提示，恢复后自动重试。预览成功并与当前状态一致后才记录缓存版本，失败或被丢弃的响应不再阻止后续刷新。真实无候选时仍不画黄色墙，不沿用失效候选。


## 执行停车选点终点导航

保持强停，在地图选取空地终点并点击“预览选点路线”。预览成功后 30 秒内可点击“开始行驶到终点（解除强停）”：该按钮明确解除强停并启动自动终点导航，不需要开启人物跟随。Nav2 根据最新地图重新规划，实际路线可能与预览不同。地图修改、其他预览覆盖或旧任务未结束时拒绝执行，需重新预览。

固定终点导航不依赖人物可见性；仍检查定位及所启用传感器的新鲜度并限制速度。手动模式、跟随模式切换及强停会取消该任务；“停止终点导航”也会锁存强停。到达或失败后不自动重复发送目标。代码接入使用原有唯一速度发布通道，没有第二个底盘速度发布者。需重启服务并刷新网页加载，首次在空旷区域低速核对，尚未完成实车验证。


### 导航生命周期响应超时

新增 `startup_watchdog.py` 只读查询 controller/planner/navigator 的生命周期状态，保留原 Nav2 管理器及运行时 bond 健康检查。25 秒无状态推进或总等待超过 65 秒时中止本次启动并记录各节点状态（1 未配置、2 未激活、3 已激活）。不会盲目重复发送配置请求，也不会将查询失败视为激活成功。退出时给生命周期管理器有限的 TERM/KILL 等待时间，避免新启动继续遗留卡住的管理器；此前已经残留的进程仍需按原清理步骤处理。这是启动失败处理改进，不能消除底层 ROS 2/DDS 响应丢失。


### 终点导航的短暂视觉断流

固定终点执行时，视觉障碍数据年龄超过 1.2 秒立即输出零速度，但在最后一次成功发布数据的源时间起 2 秒内保留任务；没有延长可运动数据有效期。新有效视觉数据恢复后丢弃等待期间速度，收到新的控制器指令才继续。数据年龄超过 2 秒、TF/雷达异常、近距障碍或无效深度仍取消；取消后不自动重启。无障碍的有效帧照常更新时效，不会因为候选数为零而停车。此修改处理短暂断流，不等于解决上游深度推理延迟。


### 原地转向的进展检查

控制器改用本机已安装的 `nav2_controller::PoseProgressChecker`：相对基准位置移动 0.15 米或朝向变化 0.15 弧度（约 8.6°）即计为进展。10 秒内两者均未达到仍停止，避免真正卡住时一直执行。此前只统计平移，低速掉头时即使持续旋转也可能被误判为无进展。此修改不提高速度、不开放倒车；实车只倾斜一点的底盘响应问题仍需结合角速度和里程计验证。使用自定义 `NAV2_PARAMS` 时也需同步这三个进展参数。停车后重启服务加载。

Nav2 实际输出角速度上限调整为 ±0.4 rad/s（约 23°/秒），前进上限为 0.18 m/s，倒退上限为 0.15 m/s。DWB 角速度上限为 0.4 rad/s，最终由接入层和网页速度设置共同限幅；网页上限若低于 0.4 rad/s，仍取较低值。只提高上限，不强制每次按最大角速度旋转，不绕过碰撞、超时或进展检查。停车后重启加载。


### 减少转向时路径更新和角度微调

两个导航行为树的全局重规划频率由 2 Hz 调整为 0.5 Hz（约每 2 秒一次）；局部控制仍按 20 Hz 工作，实时碰撞检查保留。DWB 的 `PathAlign.scale` 从 24 降为 12，降低路径对齐在轨迹评分中的权重；这不是固定的沿途角度放行阈值。终点 `yaw_goal_tolerance` 从 0.5 调整为 0.7 rad（约 40°），只放宽抵达后的朝向要求，位置容差仍 0.15 米。全局绕行路径响应可能比以前慢，局部无安全轨迹时仍停车。未更改车身、禁区或传感器有效期；停车后重启加载，需实车核对是否改善微调。


### 固定目标沿用已规划路线（当前行为）

取消行驶中的定时全局重规划，两个行为树使用顺序执行：先计算一次路径，再持续执行该路径。相同导航任务内，普通视觉候选刷新不会重新下发全局路径。本节取代上文每 2 秒重规划的说明。局部控制仍会调整速度和转向以沿原路径行驶，因此不能保证方向盘完全不微调。

实时碰撞检查、0.7 米近距视觉停车条件、定位及传感器超时检查继续生效。原路径无法安全通行或控制器判定无进展时，任务失败停车，不自动绕行重规划；需重新预览并开始导航。检测不到障碍不能证明安全。人物跟随目标稳定移动超过既有阈值时仍会取消旧任务并生成新目标路径；固定选点模式没有此目标更新。修改后停车重启服务生效。

网页地图缩放条旁新增“显示紫色缓冲区（仅显示）”复选框，默认勾选，取消后仅隐藏紫色代价区域；红色障碍、墙体、路线和车位保持显示。此项不修改 Nav2 膨胀半径或碰撞检查，不发送后端控制请求；刷新页面恢复默认勾选。


### 实际关闭或调整导航缓冲区

地图缩放处的“启用紫色禁入缓冲（整车不得进入）”及 0～1.5 米滑块控制两张地图的 `inflation`。先强停，调整后点击“应用缓冲设置”；后端写入两张地图并读回确认一致。关闭或设为 0 可真正去掉紫色膨胀，完整车身及原有 5 厘米 padding 检查仍保留。半径按 5 厘米栅格离散化；滑块不是车身半径，也不替代 footprint。

设置会清除旧预览，需重新规划；写入或读回失败时禁止新增导航，保持强停并重新应用。选择只对本次运行有效，重启使用 YAML 默认值。首次更新需停车重启 Nav2、视觉服务并刷新网页。“显示紫色缓冲区”仍仅控制颜色显示，不改变碰撞检查。


膨胀设置接口已改用独立 ROS 参数客户端和执行线程，避免主单线程执行器等待运动锁时无法处理参数响应。写入响应超时后不重复写入，而是读取两张代价地图实际值；仅两者与请求一致才反馈成功并解除设置未确认拦截。查询也失败或值不一致时仍保持拦截。需重启视觉服务加载此修复。


### 按车身宽度和转弯空间规划

默认全局规划器为本项目 `visual_car_nav2::Planner`，预览和实际导航使用同一 `GridBased` 插件。车身 0.494 × 0.364 米，四周 padding 0.05 米；无额外缓冲时，直行净宽须大于约 0.464 米，实际还受栅格离散、转角、定位误差影响。紫色半径为 r 时，平行墙间还需为两侧缓冲留出约 2r 的额外空间。

采用前进 Dubins 运动原语、0.4 米最小转弯半径、72 个朝向和完整扫掠碰撞检查。转弯半径是待实测参数；搜索有 3 秒和展开次数限制，无可验证路径或超时就拒绝执行，不退回中心点最短路。局部 `WholeBodyCritic` 在原生 DWB 前检查每条候选轨迹的完整车身扫掠，紫色、障碍和未知单元均不可进入。自定义 `NAV2_PARAMS` 必须配套这三种本地插件，启动文件会拒绝混用旧规划器/膨胀层。

本机已编译；换机器或修改插件源码后，在项目根目录执行 `bash nav2/whole_body/build.sh`。构建、测试、安装产物都在 `nav2/whole_body/`，启动文件仅给 Nav2 子进程添加该插件搜索路径；没有修改系统 Nav2 或底盘驱动。模型检查不能补偿错误车身尺寸、定位漂移或未检测到的实物。


路径穿越手绘禁区的补充修复：边界发布器改订阅编辑后的地图，完整保留内部墙体和手绘障碍，而非用全自由内部覆盖。停车预览返回前，使用实时带 padding 的车身轮廓逐段插值，检查多边形内部与边缘是否占据静态墙、手绘禁区、最新局部代价图中的视觉障碍/紫色禁区或图外区域；失败则拒绝预览，不允许执行该预览。此复核独立于可关闭的紫色膨胀；实际行驶仍依赖 Nav2 最新代价地图和局部碰撞检查。重启后重新预览，旧预览不再使用。


### 自检修复：参数通信及路径一致性

视觉开关的 ROS 参数通信已独立于主控制节点的单线程执行器，避免持锁等待响应时阻塞。预览的车身扫掠复核放到后台线程，完成后核对预览序号；强停、清除或新预览会使旧结果失效。

固定选点执行现改为 `FollowPath` 执行已经复核的完整预览路径，取代此前重新发送 NavigateToPose 的方式。开始前再次复核手绘地图和车身，确认预览未过期、版本未变；当前车位偏离路径起点超过 5 厘米或约 5.7°时拒绝执行，要求重新预览。不会按网页抽稀后的折线执行。人物跟随现同样先调用 ComputePathToPose、整车复核，再用 FollowPath 执行，实时局部避障和停止门控保留。需重启服务加载。

### 零膨胀与完整车身避障的实现

之前依赖 Smac 的膨胀代价快速检查，并用原生 DWB 的障碍评分；这不能满足“零膨胀仍检查整车，非零膨胀整车不进紫色区”的约定。现在以本项目插件替代这三处扩展点，原生库保持不变：

- `whole_body/src/geometry.hpp`：填充车身多边形与障碍栅格相交检查、平移与旋转的扫掠检查；细障碍在车身中间也不能漏掉。
- `whole_body/src/search.hpp`：朝向感知搜索，每段原语和终点连接都检查完整车身；返回全部检查过的路径样本，不用未校验直线替换弯道。
- `whole_body/src/plugins.cpp`：全局规划器、可为零的紫色硬禁区层和 DWB 轨迹否决插件。
- `path_clearance.py`、`route_preview.py`：预览返回前及开始行驶前复核当前静态地图、局部代价图与完整车身；旧预览不直接放行。
- `params.yaml`、`follow.launch.py`、`inflation_control.py`、专用 `frontend/nav2-inflation.js`：统一两张地图和网页语义，移除强制 0.60 米膨胀。

离线构建和测试（不启动底盘、不发布速度）：

```bash
bash nav2/whole_body/build.sh
```

测试覆盖零/非零紫色缓冲绕障、窄通道、车身内部细障碍、转角扫掠和三个插件加载。旧 `tests/native_clearance/` 保留为 Smac 原行为的复现工具，当前不再使用它的“基础膨胀”方案。启动指令统一见上方“所有启动项指令放这里”，加载新插件需要停车重启服务并重新预览。

### 黄色视觉墙消失时的筛选诊断

黄色墙开关勾选只表示允许显示，不代表本帧一定有有效障碍。视觉开关下方现在显示筛选原因、相机墙格数和地图墙格数；`GET /api/nav2/vision-enabled` 的 `diagnostics` 提供有效深度、距离/横向范围、高度、连通面积、地图裁剪和最终选择各阶段的点数。

已修复两处新增接入问题：先对完整视觉候选进行面积去噪，再裁剪地图，避免地图边缘的有效片段因不足 6 个像素被二次删掉；相机黄墙不再完全依赖地图裁剪结果。有地图内候选时，相机与导航使用同一候选；没有地图内候选但视野中有候选时，仅在相机显示最近候选，并明确标注“地图外，仅供相机预览，不写入导航地图”。图外检测仍不添加到小地图，近距停车仍检查全视野有效候选。

这些更改没有调整原相机或深度模型，也没有自动缩放单目距离。若显示距离、高度或地图范围导致候选为空，应核实相机安装高度、俯角、车位和深度比例，不能把无标注当作无实物障碍。黄色墙仍只在强停时预览，过期数据不绘制。需重启视觉服务并刷新网页加载这次修改；不会自动重启或解除强停。

### Nav2 视觉距离校准与近处零散车架

在“启用视觉障碍检测”提示下，展开 **Nav2 视觉距离校准（需强停）**：

1. 强停，保持相机与障碍物不动，点击“获取校准画面”。这里使用深度结果对应的同一帧原图，而非最新视频帧。
2. 点击最近物体内部的一块实心表面，例如手推车立柱或面板；避开边缘、镂空和背景。
3. 输入**相机光学中心到选中表面的直线实测距离**，单位米，再点击“应用 Nav2 测距校准”。“不到一米”不作为精确值，需量出该点距离。画面 60 秒失效，过期需重新获取。
4. 等待新帧，核对黄色墙和地图位置，再重新预览路线。应用会取消旧导航、清除旧预览并保持强停，不启动小车。

比例仅作用于新增 Nav2 深度消费者：同时影响障碍位置、高度筛选、地图裁剪、黄色墙和近距停车。原人物跟随测距、相机配置、模型权重均不改。选点按去畸变视线把光轴深度换算为直线距离，避免侧方选点的距离定义错误；深度不连续或无效的选点拒绝应用。比例仅本次运行有效，重启恢复 `NAV2_VISION_SCALE`（默认 1）。单点校准不能保证所有场景或距离准确，应在其他距离核验，不能把有颜色视为测距已可靠。

最近候选现在会同时保留与种子候选距离差不超过 0.30 m、平面包围盒间隔不超过 0.20 m 的有效连通片段，减少同一近处车架只剩单根立柱的情况。该方法是几何候选聚合，不是整车语义识别；不填充未观测空隙，也不保证完整提取整辆手推车。仍先校正比例再做距离/高度筛选，地图外候选不写入导航地图。

本功能由 `nav2/vision_calibration.py`、`nav2/vision_layer.py`、`nav2/vision_toggle.py` 及已有 Nav2 专用 `frontend/nav2-vision-toggle.js` 实现；页面入口由专用脚本生成，未改共享 HTML 或原视觉代码。重启视觉服务并刷新网页加载，不会自动重启服务。

### Nav2 独立 YOLOE 检测与分割

新增 `nav2/semantic_obstacles.py` 使用 `nav2/models/yoloe-26n-seg-pf.pt`（官方免提示版本），不下载文本编码器，不更新 Ultralytics、PyTorch 或原 `yolo26n-seg.pt`。模型路径可由 `NAV2_YOLO_MODEL` 指定。默认 `NAV2_YOLO_DEVICE=cpu`，避免占用原人物模型的 GPU；机器资源仍是共享的，部署时应观察原有处理帧率。关闭视觉障碍时停止这个工作进程，未启用 Nav2 时不使用它。

工作进程独立加载模型，最多 2 Hz、一次仅一个在途请求；接收结果后必须与原始深度帧的配置版本、视频周期匹配，帧龄不超过 1.2 秒才融合。加载失败、没有识别结果或过期均明确显示，原有深度候选和近距检查仍保留，不把模型失败当无障碍。

限定识别手推车（handcart/cart/trolley/shopping cart）、椅子、桌子、柜子、箱子等实体类别，排除免提示模型中的抽象背景标签。同一实例内不连通的有效深度片段可以保留；仍执行距离、高度及地图裁剪，不用外接框填满物体空隙，不放行更近的未分类障碍。物体类别不提供可靠米制距离，原有 Nav2 距离校准仍适用。

网页开启原来的视觉障碍检测及黄色墙预览后，地图旁同一个相机窗口增加**青色识别轮廓、英文类别及置信度**，使用分割对应的原始帧与位姿，避免画到另一帧上；黄墙仍是有效深度投影，红墙仍是手绘禁区。没有另建视频窗口，也没有修改原相机画面输出。

现场保存图离线测试：该版本识别出 file cabinet、storage box、chair；**没有可靠识别出用户所指的手推车**。因此本次完成的是独立 YOLOE 接入，不能承诺这辆推车已被识别完整。若要覆盖这类推车，需进一步验证文本/视觉提示模型或专门训练数据，不应将其他类别改名伪装成手推车。未自动重启服务、解除强停或执行行驶；重启视觉服务并刷新网页后加载新增代码。


### 人物作为目标的整车路线执行

开启 Nav2 后，使用网页原有的目标 ID 选择和“开始跟随”按钮。只有自动跟随已启用、强停已解除、选定人物可见且距离/方位数据新鲜时，原控制接口才触发新增的 `person_navigation.py`；只检测到人物不会自动解除强停或开始行驶。

流程：人物同帧距离与方位 → 相机外参及 odom 车位换算 → 连续 3 帧稳定目标 → `ComputePathToPose(GridBased)` → 与手动选点相同的整车/紫色禁区复核 → `FollowPath` 执行返回的完整路径。使用 `whole_body` 的同一全局规划器及 DWB 整车轨迹检查，不另行切回中心点最短路线。

人物位置作为导航参考，实际停车终点保留网页设置的跟随距离，不把车身中心驶到人物脚下；已在跟随距离内则停车。沿用滚动地图单次最多 3 米的目标截断，远处人物可能分段接近。正在执行时，小幅目标抖动不会重规划；稳定人物在 odom 中的位置移动超过 0.5 米且距上次目标至少 2 秒才取消旧任务，等待取消完成后更新。规划阶段若稳定人物位置已移动超过 0.5 米，也丢弃旧规划。

规划或复核期间输出为零。完整流程超过 5 秒、没有有效路线、车位偏离起点超过 5 厘米/约 5.7°、目标数据超时、目标 ID 改变、强停或切换手动，均不允许迟到结果开启行驶。人物路线不标记为固定终点任务，保留原有目标丢失停车门控。`nav2_person_navigation` 状态提供 `planning/validating/executing/arrived/error/idle`；原运动状态同时显示规划、复核等待或错误原因。

修改范围：新增 `nav2/person_navigation.py` 和测试；接入原先新增的 `nav2_follow.py`、`nav2/route_preview.py`、`nav2/point_navigation.py`，没有修改原 `control.py`、相机服务、识别模型或底盘库。需停车重启当前 Nav2/视觉服务，刷新网页后使用原跟随按钮。新增流程经离线异步回归测试，未进行实车跟随验证。


### 转弯限速与人物移动误判修复

导航原先分别裁剪线速度和角速度，会把 `v=0.30、w=0.50`（半径 0.60 米）改成 `v=0.15、w=0.40`（半径 0.375 米）。现在 `nav2/motion_geometry.py` 的 `limit_twist()` 按相同比例缩放两者，该例输出 `0.15、0.25`，保持原转弯半径。也提前考虑原控制中的用户速度上限，避免下游再次分别裁剪；两张地图不变，DWB 的线速度/角速度上限同步为 0.18 m/s、0.4 rad/s。

重规划现在比较人物在 odom 下的真实测量位置，不比较随小车位置变化的跟随停车点。连续帧滤波作用于人物位置；每次生成任务记录人物位置作为基准。小车自身绕行不再因停车点变化误取消路线，真实人物稳定移动超过阈值仍取消旧任务并重规划。人物位置比较不受单段目标 3 米截断影响。

这些修复不等于保持人物永远可见：当前搜索尚未添加相机视野约束，转弯造成出画或遮挡仍触发原有停车保护。没有放宽丢失/超时检测，也没有开启看不见人时继续行驶。更新需要停车重启 Nav2 和视觉服务；本次仅离线验证，未运行实车。


### 分段跟随：终点锁定，到达后重新确认人物

当前段规划并开始执行后，人物在 odom 中没有超过 0.5 米的稳定移动，沿用原终点和完整路线，不随每帧检测或小车自身转弯重新计算终点。超过阈值仍沿用既有的明显移动更新规则；强停、目标丢失、超时和实际碰撞风险仍可提前停车。

收到当前 FollowPath 成功到达结果后，立即清零输出并清空本段累计的人物滤波样本。下一段只接受拍摄时间晚于到达时刻的人物测量，重新等待连续 3 帧稳定确认；不能把到达前拍摄、到达后才处理完的旧帧当成新目标。确认后，人在跟随距离内则保持停车，否则再按相同的整车绕障方法规划并执行下一段。仍追踪当前选定 ID，不会自动切换到其他人。


### 有预览路线但开始行驶返回 409

修复新增导航的空闲停止竞态：原视觉循环在强停期间会重复通知停止；此前每次通知都递增导航 generation，导致耗时的路径复核前后版本不同，合法的启动被“状态已改变，请重新预览”拒绝。现在仅存在活动/待接受/取消中任务时才递增任务版本，重复空闲停车保持幂等。真正的强停、配置切换仍通过清除预览/预览序号变化阻止旧路线执行，运行中任务取消保护不变。

`point_navigation.py` 现在将 409 的具体原因写到 control.log，便于区分过期预览、位姿偏移、地图变更和碰撞复核失败；不能仅凭历史访问日志中的 409 判断所有拒绝都来自此竞态。现有运行进程需重启才能加载修复。

操作顺序：保持强停，重新选点并完成预览，在 30 秒内直接点击地图区域的“开始行驶”。该按钮在校验成功后切入固定终点导航；不要先单独解除强停，那会清除预览。无效路径、真实状态变更仍会拒绝执行。

### 选点启动与视觉数据等待

启用视觉障碍检测时，“开始行驶”先检查数据是否新鲜；若短暂过期，保持强停并在当前请求内等待更新，不会后台排队启动。等待期间不反复计算整条路径、不持有运动或导航锁休眠。两秒等待预算从首次发现过期开始，数据更新后重新复核路径、地图版本和起点；持续超时、手动强停或预览变化均拒绝启动。数据有效期仍为 1.2 秒，未放宽停车保护。

`data/runtime/control.log` 中可查“选点路径复核耗时”“选点启动锁等待”和“视觉更新延迟”。最后一项分别记录源帧年龄、读取深度缓冲耗时、语义阶段、导航锁等待和障碍计算耗时，避免把启动拒绝误判为底盘或规划器故障。代码修改后需停车并重启服务才生效。

路径复核现由 `nav2/clearance_worker.py` 在独立 Python 子进程执行；网页选点与人物路线共用此入口。静态地图和局部地图仍逐一检查完整车身扫掠范围，原有碰撞算法未删减。子进程只接收路径/地图快照，没有 ROS 节点或运动接口；最多同时一个复核，单次超时 3 秒即拒绝，不跳过检查。数值库线程数仅在子进程内限制为 1，不改变原视觉程序设置。此隔离用于减少复核与视觉回调的解释器竞争，实车是否恢复仍须结合启动日志验证。

弯道控制性能修补：视觉障碍地图仍逐帧更新内容，但其 10 米窗口原点只在小车离开中央 5 米区域时重置，避免每移动 5 厘米触发 StaticLayer 重建。本项目 WholeBodyCritic 每个控制周期建立一次非零障碍格索引；扫掠外包区域完全无障碍时走快速判定，否则保持原完整几何检查。紫色区、未知区、车身尺寸、速度指令 0.3 秒失效保护及进度超时均未放宽。需停车重启以加载新 Python 代码和本地插件。

视觉导航更新现使用 `nav2-vision-update` 独立串行线程，直接读取原深度缓冲中的最新结果；不再用原相机节点的单线程 ROS 定时器执行障碍计算。原相机、跟踪和深度推理代码保持不变。线程不并发处理、不积压旧帧，异常时使视觉状态失效并停止导航；服务关闭时停止线程并由它关闭 YOLO 子进程。日志新增“回调间隔”“入口帧龄”，用于区分调度延迟与上游源数据已经过期。仍使用真实采集时间检查 1.2 秒有效期；若深度源本身停止产出，仍会停车，不能依赖该隔离绕过超时。

视觉深度接入：`nav2/depth_mailbox.py` 在深度完成回调旁增加一个仅保存最新结果的导航缓存，让导航无需等待人物融合队列。原回调仍原样调用一次，原相机/跟踪/深度文件及模型参数不变；关闭导航线程时恢复回调。缓存拒绝旧配置、旧相机流和时间倒退的结果，采集时间戳不改写。日志“视觉深度分段耗时”包含 `input_wait`（采集到推理开始）、`inference`（推理耗时）、`after_inference`（推理完成到导航读取）；它们用于继续定位真实源数据延迟，不代表已确认所有超时根因。

导航前进速度已从 0.15 小幅提高到 0.18 m/s（20%），DWB 与项目接入层同步；角速度仍为 0.4 rad/s，倒退输出上限仍为 0.15 m/s（当前 DWB 未开放倒车）。网页较低限速仍优先生效，线/角速度按同比例缩放，避免改变转弯曲率。进度检查仍为 10 秒内移动 0.15 米或转动 0.15 弧度，未用延长超时掩盖停滞。`control.log` 中每两秒记录一次“导航速度检查”，包含控制器速度、放行速度、拦截原因和数据年龄；提速本身不保证解决进度超时。

### 人物地图与避障跟随

“地图与导航路线”下新增人物定位状态和“开始避障跟随”按钮。获得同帧有效距离、方位及历史 TF 后，小地图以橙色三角形标出当前所选人物 ID，紫点标出其他人物；短暂掉帧时保留源帧起 3 秒内的最后位置，用淡色虚线标记并注明“最后位置，待确认”；普通实时跟随要求新鲜同帧测量；显示缓存本身不能驱动车辆。下文“记录人物点并规划 → 开始追踪”是单独的明确锁定路线入口。标点只是读取数据，不触发运动，定位准确性仍受相机外参、距离估计和里程计影响。

使用现有“避障跟踪 ID”选择目标，确认自动模式并按原流程解除强停，再点击“开始避障跟随”（或原来的开始跟随按钮）。系统复用已有稳定目标滤波、整车路径计算和复核，成功后执行同一 FollowPath 链路；绿色路线显示已复核的人物执行路径，绿色方块是保持跟随距离的停车终点，人物标点并非要求车身到达的人体位置。已在跟随距离内不前进；无有效路线或传感器过期保持停车。

新按钮不会解除强停、不会覆盖正在执行的选点导航，也不会创建第二套跟踪器。目标切换、目标丢失及强停仍沿用原安全逻辑。网页新增接口 `/api/nav2/people-map` 只读，`/api/nav2/person-start` 仅由用户点击触发；原相机和底盘文件未修改。修改后需停车重启服务并刷新网页。


### 人物标点掉帧与人体占用区（2026-09 修复）

人物在视觉障碍图中的红色占用区仍属于真实障碍，不会因为被选为跟随目标就清除。此前停车终点只取人物与小车连线上的一个点；该点的整车轮廓若落入人体占用区或紫色禁区，规划会报 `Goal footprint touches obstacle, buffer or map edge`。现在人物预览和自动跟随都先尝试原停车点，规划器返回失败后，再依次尝试离人物稍远及接近侧两边的停车点（最多 9 个，保持原跟随距离下限和单段 3 米上限）。候选只是在找停车点，必须通过同一个 GridBased 规划器和整车路径复核；不能穿过人体、墙或手绘禁区。人工选点终点不会被替换。

所有候选共用原来的 5 秒规划/复核期限；强停、目标 ID 改变、目标丢失/超时和旧任务取消仍阻止路线执行。没有候选可达或复核失败，仍保持停车，不会为取得一条路线删除障碍或放宽碰撞条件。

人物图标之前直接随最新检测有效性删除，因此漏一帧、距离暂缺或接口短暂失败都可能闪烁。现在 `person_map.py` 保留最多 3 秒的**显示缓存**，按原始拍摄时间计时，不靠轮询续期；相机流、配置或选择 ID 改变会清除旧缓存。淡色橙三角只说明最后看到的位置，不代表当前仍锁定，也不能启动车辆。

已执行的人物路线停止后，可在小地图保留 15 秒灰色虚线历史路线，并显示停止原因。历史路线与绿色执行路线分开存储，不能提交给运动接口；普通实时跟随目标丢失时停车，已明确锁定段按下文 R31 规则执行。此显示改动不修复识别模型漏检，也不延长运动数据有效期。

仅修改导航接入模块及导航专用前端脚本，没有修改原相机、底盘控制、启动脚本或安装的 Nav2 库。停车后按本文原启动方式重启服务，再刷新网页生效；离线回归通过，仍需现场验证人体定位和停车点。


### 点击锁定历史人物点并规划

R33 将点击规划的历史位置与 3 秒实时显示缓存分开：**记录人物点并规划** 使用当前人物 ID 在当前相机流/配置下最后一次有效的 odom 位置，**不设 3 秒或其他年龄上限**，立即显示橙色描边圆点 **历史人物点 ID…（点击锁定）**，同时请求整车停车路线。历史坐标保留真实采集时间，不把旧点标为实时检测；切换 ID、相机流/配置或重启进程后须重新看到人物。原“停车预览路径”也接入同一接口；整理布局后隐藏重复入口，统一使用“记录人物点并规划”。

历史点与实时橙色三角形分别显示：点击历史点不随短暂漏检删除，重新点击可更新，切换所选 ID 或相机流/配置后清除。刷新页面可从后端恢复。点保留不代表路线可执行；规划失败也保留点，并显示具体错误。当前人物从未有有效位置时拒绝请求，不会凭空创建位置。规划使用捕获时的地图坐标，保留跟随距离及人体占用区，仍做整车避障复核。

地图下的“开始追踪”执行刚才成功预览的人物路线，操作步骤见下节。该段不因实时人物闪烁、丢失或移动而重定终点；到达后，单次模式结束，连续模式等待新的稳定人物测量再规划下一段。切换 ID、相机配置或停止会使原授权失效。点击锁定点与灰色已停止历史路线是两种数据；灰色路线不能用于启动。

修改位置：`nav2/person_map.py`、自有 `nav2_follow.py` 和导航专用 `frontend/obstacle-map.js`；未修改原 `control.py`、`frontend/app.js` 或底盘代码。停车后重启服务并刷新网页加载。


### 人物路线旁的“开始追踪”

停车状态下，先点 **记录人物点并规划**。有效预览完成且后端启动条件满足时，旁边的 **开始追踪** 可用，无需等待人物重新出现在当前画面。点击即明确授权切换自动模式、解除软件强停并沿刚才的路线行驶；无需先去其他区域解除强停。原强停按钮可随时中止。

`POST /api/nav2/person-execute` 要求已锁定的人物点有效、当前人物预览序号一致、预览不超过 30 秒、旧导航已结束；复核最新地图上的整车通行空间，并再次核对所选 ID、相机配置、车身未偏离路线起点超过 5 厘米/约 5.7°，以及导航和传感器状态。执行已有锁定路线不再重新索取实时人物位置，也不因人物离开参考点超过 0.5 米而拒绝。全部通过才发送同一条 `FollowPath`，不会清掉预览再重新计算。检查失败保持停车并显示原因；重复点击不会重复发送任务，发送异常恢复强停。

R31 将这个明确点击执行的任务标记为已锁定路径段，单次和连续模式途中都不因人物丢失或移动而取消、改线；到达、失败或停止后不重发该单次任务。实时整车碰撞、近距障碍、定位/视觉数据和速度时效检查继续生效。历史点仍需有效规划、复核及用户点击才能行驶，灰色已停止路线不能授权。新接口位于自有 `nav2/person_execution.py`，与 `person_navigation.py` 共用执行提交代码；不修改原相机、底盘控制或 Nav2 安装库。停车重启服务、刷新网页生效。


### 连续人物追踪（到达后才更新路线）

人物规划按钮旁新增 **连续追踪：到达后更新终点，1 米内等待** 复选框（默认勾选），以及 **结束追踪** 按钮。使用步骤：启用视觉障碍检测 → 停车规划第一段人物路线 → 勾选连续追踪 → 点击开始追踪。勾选状态只在启动时提交，行驶中不能修改。

- 第一段执行刚才预览的路线；行驶及规划过程中冻结人物终点，不因人物移动或实时图标闪烁重新定位、取消或重规划。本段使用已有固定路径执行门控；人物暂时离开画面时继续已复核的本段路线，不使用旧人物位置生成下一段。
- 收到控制器成功到达结果后停车，清空旧滤波数据，等待到达后拍摄的连续 3 帧稳定人物测量，再规划、复核并执行下一段。沿用已选 ID，后续段保持 1.0 米跟随距离，单段目标最多推进 3 米。
- 已在 1 米范围内时保持连续模式但输出为零；人物离开 1 米范围后，经 3 帧稳定确认再生成下一段。到达后看不到人物则原地等待，不猜测新终点。
- 视觉新障碍触发停车后，R32 会保持本段原终点，等待旧动作结束，再重新规划并复核绕行路线；通过才继续。无有效绕路、超时、执行失败或 ID 改变等异常会锁住自动续段，需要重新规划并点击开始追踪。定位、视觉数据时效及强停保护继续生效，详见下节。
- **结束追踪** 关闭连续模式和跟随授权并强停；普通强停同样能中止运动。未勾选连续模式时，“开始追踪”只执行当前锁定段，到达或失败后结束，不自动生成下一段。

连续模式要求视觉障碍检测已开启。R31 把“已点击锁定段不因人物丢失取消”同时用于单次“开始追踪”；前文普通实时“开始跟随”入口仍要求实时人物。两种入口没有共享延长的人物有效期，且均保留障碍、车身或传感器失效检查。新增行为只在自有导航接入和专用前端内实现。停车重启服务并刷新网页生效，尚需现场验证。


### 遇障停车后自动绕行原终点（R32）

使用原启动命令，启用视觉障碍检测后，**记录人物点并规划 → 开始追踪** 的单次锁定路线及连续追踪各段自动获得本功能，无需新增勾选项。普通实时跟随入口、人工地图选点及未启用视觉检测时保持原行为。

1. 行驶期间，每次视觉更新检查剩余路线上的全量候选，包含地图外点。确认障碍会与整车路径相交，或原近距保护触发时，立即清零输出并保存本段实际停车终点；不重新读取人物位置。
2. 取消旧 `FollowPath`，必须等它的终态确认。仅收到取消请求回应还不能提交新动作；旧任务恰好成功到达时按到达处理。
3. 从停车位置调用同一个 `GridBased` 规划器，目标仍是原终点（含原朝向），不尝试人物周围的其他终点。新路线同时通过最新静态/全局图、紫色禁区、完整车身和全量视觉点扫掠复核。
4. 复核通过后自动沿新路线继续。实际限速及平滑后的每个速度指令还必须通过全量视觉点的短时整车扫掠检查，含数据延迟与制动位移；因此障碍仍在前方矩形内但安全转向绕开时不会永久卡住。该分支只适用于本轮已复核绕行任务，不清掉障碍或放宽视觉/TF时效。
5. 到达后，单次模式结束；连续模式等待到达后采集的 3 帧稳定人物数据，超过 1 米继续下一段，1 米以内等待。结束追踪、强停、切换人物 ID 或相机配置立即撤销任务，迟到规划结果不能恢复运动。

旧动作终态最多等 5 秒；规划与整车复核共用 5 秒期限。无路、校验失败、传感器失效或超过期限均保持停车，不无限重试。每个人物段最多自动重规划 3 次，超过后提示检查障碍并重新开始；成功到达后下一段重新计数。控制页面沿用现有状态文字，`data/runtime/control.log` 可搜索 `Nav2 遇障重规划`、`Nav2 绕障路线已提交`、`Nav2 障碍绕行停止`。

完整路线扫掠在控制锁外运行；车身轮廓按它自身时间戳的 TF 转回车身坐标，避免混用较新的车位导致轮廓偏移。新检查沿用原已加 padding 的车身与 5 cm 障碍占用格，不额外增加原规划器不知道的缓冲距离；紫色缓冲仍由原整车规划器和全局地图复核约束。

本轮只改自有 `nav2/` 模块及自有 `nav2_follow.py`，未改原控制/相机文件、前端或安装的 Nav2 库。停车后重启原服务生效；离线验证不代替现场定位、视觉深度和制动能力核对。启动仍为：

### 历史点 3 秒限制与途中 TF 超时修复（R33）

当前日志中的两项问题分别是：人物规划被“最近 3 秒没有所选人物的有效世界位置”拒绝；手动选点已经收到 `FollowPath`，约 23.5 秒后接入层报“里程计 TF 超时”并取消。后者并不是规划器报告无路，也没有触发人物遇障重规划日志。

- 历史位置现在独立保存，显式点击规划不限制其年龄。30 秒**路线预览**期限、最新地图复核和当前位置检查仍保留；过期路线可使用同一个历史点重新规划。连续模式到达后的下一段仍等到达后 3 帧有效人物测量，不把历史点当新观测反复追踪。
- 自有 `pose_listener.py` 用独立 ROS 节点和线程接收导航 TF。原接入将 TF 与导航回调放在同一个单线程执行器，导航回调等视觉线程的导航锁时可能让 TF 入队后无法更新。独立接收不迁移原相机/运动节点，**不延长原来的 0.5 秒 TF 时效门槛**；真实定位失效仍停车。新报错附源时间差，便于区分定位源失效和调度问题。
- 新增绕行的轮廓读取仅复制车身图层，不再取完整地图快照和编辑锁；重复、过期或视觉关闭的帧不再重复做这项读取。普通手动选点不运行人物路线重规划监测。

以上是针对已证实拒绝条件和代码中线程耦合的修补。旧日志未保存 TF 超时时的具体年龄，不能据此断言底盘 TF 源当时一直正常。需要停车重启服务后验证实际运行；若仍停车，请以新增的具体停止原因继续排查。未改原控制、相机、前端和安装的 Nav2/Ranger 库。

### 开始追踪后立刻取消：视觉等待冲突修复（R34）

本次日志：人物执行接口返回 200，控制器接受 `FollowPath` 后 **0.651 秒**取消；接入层记录“视觉障碍数据超时，停车等待新数据”。新增的剩余路线监测把 `VisionStale` 落入通用异常并调用 `stop()`，绕过了原固定路线的短暂等待。这是自有绕行监测与已有等待行为的冲突。

修复位于 `replan_support.py` 和自有 `nav2_follow.py`：

- 运行中的路线监测与速度扫掠统一区分短暂过期。源帧超过 1.2 秒立即零速，保留当前固定路线等待；最多等到该数据的源年龄 2 秒，反复检查不能延长期限。持续超时仍取消。

- 几何计算结束后再次检查源年龄；计算途中变旧的结果不能放行速度，也不能被当成新障碍触发重规划。

### 近距障碍与速度平顺性优化

近距保护由 `nav2/near_obstacle.py` 实现，仍使用全部有效视觉候选（包括地图外候选），不因“只显示最近障碍”而漏掉停车检查。最低阈值保留前方 0.70 米，增加 `前进速度 × 源帧年龄 + 速度² / (2 × 0.5)` 的提前量；转弯时检测半宽由 0.40 米扩大，最多到 0.55 米。距离仍是 base_link 坐标下的前向距离，这些参数是保守启发式，不能替代实测制动能力或单目深度标定。

危险进入不等待多帧，单个有效近距候选仍可立即触发停车。解除障碍状态需要超出停车阈值至少 0.12 米，并连续 3 个不同源帧确认安全；停车后保留触发时的释放距离和宽度，避免因为速度归零而马上缩小保护范围。数据过期不能算安全帧。这里只解除感知状态，不解除强停，也不解除连续模式异常后的暂停。R32 成功复核的绕行任务会单独使用实际运动方向的整车扫掠门控，不能由安全帧计数擅自启动。视觉障碍状态接口中的 `diagnostics`包含最近距离、停车阈值、检测半宽和安全帧数。

自有速度接入增加 `motion_geometry.CurvatureRamp`：线速度增加率 0.30 m/s²、角速度增加率 0.70 rad/s²；同步缩放当前指令，保持当前转弯曲率，不混合旧路线方向。前进/倒退切换先过零；左右角速度修正从零限制新方向角加速，不再将整车反复归零。长时间无输出后重新缓起。最高速度不变；减速不延迟，危险、强停、过期指令、视觉暂停全部立即输出零并重置过渡状态。这里平滑的是加速，不是对紧急停车做慢滤波。

尚未实车验证平顺性或深度测距精度。改动不重新训练检测模型、不删除近距噪点、不改变整车碰撞检查，也不修改原底盘/相机代码。停车重启导航与视觉服务后生效。

### 途中视觉超时：减少接入耗时与准确计时（R35）

最近一轮固定选点任务执行约 25.3 秒，期间反复出现视觉数据过期/恢复，最后由“视觉障碍数据持续超时”取消。用户已确认测试后关闭底盘或拔线，因此随后 CAN 发送失败不能直接当作行驶期间的原因。

- **新深度结果到达即唤醒**导航视觉线程，消除原先最多约 100 毫秒的固定轮询等待。仍只有一个消费者，帧不排队；没新帧时仍每 100 毫秒检查健康状态。
- **YOLOE 障碍语义任务只提交新鲜、未处理的新帧**。同一帧不反复缩图/推理，超过 1.2 秒、未来时间、无效时间的帧不提交；结果仍照常收取，配置/视频流切换后接受新代次。原人物模型与原深度模型设置不变。
- **缓存不变的静态墙和地图外侧边框**。地图占用、原点/分辨率/朝向、坐标变换、视觉窗口或边界模式改变时立即重算；实时视觉点只写副本，避免旧障碍残留。8.4 米走廊尺寸的离线样例中，40 次比对逐格一致；墙体部分的中位耗时从约 49.24 毫秒降到 0.398 毫秒（含缓存键计算），不代表整个推理链路的耗时。

新增日志 **“视觉新帧首次消费”**：`input_wait` 是采集到推理开始；`inference` 是推理耗时；`result_delivery` 是推理完成到导航缓存接收；`mailbox_wait` 是缓存接收到首次读取；`producer_interval` 是相邻结果到达间隔；`first_read_age` 是首次读取时的数据年龄；`tick_seconds` 是这一轮视觉处理耗时。旧的 `after_inference` 仍是推理完成到本轮处理结束的累计时间，`new_frame=false` 时包含旧帧驻留时间，不能当作每帧传输延迟。
