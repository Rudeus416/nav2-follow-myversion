# 毫米波 Nav2 绕行跟随（ROS 2 Humble）

启用后，人物测量生成 `odom` 下、位于人物前方跟随距离处的目标；Navfn A* 在滚动障碍地图上规划，DWB 根据底盘轮廓选择局部速度。行为树以 2 Hz 重规划；人物目标移动超过 0.35 m 时取消旧目标并发送新目标，更新间隔至少 1 s。目标丢失时仍按原有规则停车，因此绕行幅度过大、人物离开相机视野时会停下。

速度链路：`controller_server → /visual_car/nav2_cmd_vel → control.py 强停/新鲜度/速度限制 → /cmd_vel → Ranger`。只有视觉控制向底盘发送速度。手动模式保持原来的人工控制，不经过 Nav2 绕行；此功能不包含独立 Collision Monitor。

## 安装与安装参数

本机已检查到 Nav2 1.1.20（ROS 2 Humble）所需包。换到未安装的运行机器时执行：

```bash
sudo apt-get update
sudo apt-get install ros-humble-navigation2 ros-humble-nav2-bringup
```

当前按旧控制逻辑和已保存标定，采用以下二维配置：

1. 两个 costmap 的 `footprint` 为前后长 0.494 m、左右宽 0.364 m，假设 `base_link` 位于矩形中心，顶点 `(±0.247, ±0.182)` m，额外边距 0.05 m。尺寸按用户指定的轴距、轮距设置；膨胀半径 0.8 m，自动速度上限 0.3 m/s、0.5 rad/s。
2. 启动文件读取 `data/data_transfer/20260920_160622_946624.json`，忽略其中的高度、俯仰和横滚，将雷达—相机平面变换与相机—底盘平面位姿组合，发布 `base_link → ti_mmwave_0`。默认结果为 x=-0.02 m、y=0.02 m、yaw=-2.8°（约 -0.0488692 rad），z/roll/pitch=0。**这是根据保存标定和旧控制假设推导的二维 TF，不是历史实车 TF 测量记录。** 若已有其他节点发布雷达 TF，设置 `NAV2_PUBLISH_RADAR_TF=false`，避免同一子坐标系出现多个父节点。
3. `NAV2_CAMERA_X`、`NAV2_CAMERA_Y`、`NAV2_CAMERA_YAW` 默认均为 0。旧 PID 跟随直接使用相机距离和方位，没有安装偏移补偿；现在用零值显式沿用这一假设，并非找到过实测零外参。可按实际测量覆盖，单位米、米、弧度，雷达 TF 会同步组合相机偏移。历史 `camera_height_m=0.5` 仍只是原来的测距参数，不用于本二维 TF。
4. 雷达话题 `/ti_mmwave/radar_scan_pcl`，PointCloud2 坐标系 `ti_mmwave_0`（原始 ADC 的 `radar` 不适用）。沿用跟随的 3TX profile、200 ms 帧周期和 5 m 距离上限。代价地图高度过滤上下限暂放宽到 ±1000000 m，层级上限同步放宽，使实际雷达点不会因高度阈值被排除；这是暂不考虑高度的工程设置，不是历史参数。没有改写原始点云 Z，范围判断仍可能受 Z 影响，也不做地面点剔除。

`NAV2_RADAR_CALIBRATION` 可指定 `data/data_transfer` 下其他 V2、`radar_ros` 标定文件名。Nav2 模式同时预载该文件用于原有图像投影、人物测距；这些功能仍使用完整三维标定。预载不会自动启动雷达。若传感器相对安装已改变，需重新标定。

修改话题时同步修改两个 costmap 的 `radar.topic` 和 `NAV2_RADAR_TOPIC`；修改坐标系时同步修改两个 costmap 的 `radar.sensor_frame` 和 `NAV2_RADAR_FRAME`。底盘轮廓覆盖范围、实际传感器安装位姿与高度过滤仍需后续实测核对。

## 启动

Windows 浏览器访问 `http://192.168.31.214:8890/`，实时检测图像下方、运动控制上方的“避障地图”显示局部 costmap、车身轮廓、雷达点和规划路径，支持缩放，画布最大显示尺寸为 420 × 280 像素，窄屏自动缩小。数据通过只读 `/api/obstacle-map` 接口每约 0.5 秒刷新；超过 3 秒的图层隐藏。雷达点按消息时间变换到 odom，TF 缺失时显示错误，不绘制错误位置的点。路径仅在规划后出现。地图坐标为上方 +Y、右方 +X；该区域不发送运动指令。

更新网页地图代码后需重启服务，再刷新浏览器。静态检查时保持强停，雷达或叠加模式需启用雷达；未启用 Nav2 时显示等待地图。

### 停车预览与停止原因

运动控制面板显示当前控制状态，包括强停、未开始跟随、人物 ID 未检测到、跟踪或距离超时、雷达超时、导航目标等待接受和速度等待等。显示的是软件控制条件，不代表底盘已经执行了指令。

保持强制停止，选定当前可见的人物 ID（雷达或叠加模式需启用雷达）；距离测量有效后，点击地图下方的“停车预览路径”。此按钮只请求 `ComputePathToPose` 规划，不调用导航执行动作、不解除强停、不发送速度。无需点击“开始跟随”。成功返回青色虚线，失败显示规划状态/错误码，超过 5 秒未返回则取消；预览为一次性的场景快照，30 秒后隐藏，需重新点击计算。地图缺失或过期时不会绘制预览。

停车预览的目标跟踪和距离/方位测量使用独立的 **2 秒**有效期，按钮下方显示实际数据延迟；超过 2 秒或目标不可见时仍拒绝预览。此有效期只用于强停状态下的路径预览，不改变自动跟随的运动超时限制。

目标已在跟随距离内时提示无需前进。更改配置、切换模式或强停状态会清除旧预览。若识别到了人物但无法预览，请根据按钮下方的目标/距离超时提示、TF 错误或 Nav2 规划错误继续排查。

## 启动步骤：选择雷达、地图或同时开启

在项目根目录操作。先在网页强停，然后停止旧服务：

```bash
./run.sh stop
```

**所有启动项指令放这里**

使用地图或叠加模式时，先将小车放到下文指定起点。以下启动命令**只选一条执行**，切换启动方式前先强停并停止旧服务。

**视觉障碍检测默认关闭（不带 `NAV2_VISION_OBSTACLES=1`）：**

```bash
# 只使用毫米波障碍层
NAV2_ENABLED=1 NAV2_OBSTACLE_MODE=radar ./run.sh start

# 只使用手绘静态地图，不要求毫米波点云
NAV2_ENABLED=1 NAV2_OBSTACLE_MODE=map ./run.sh start

# 静态地图与毫米波障碍层叠加
NAV2_ENABLED=1 NAV2_OBSTACLE_MODE=both ./run.sh start
```

**视觉障碍检测启动时开启：**

```bash
# 毫米波 + 视觉障碍检测
NAV2_ENABLED=1 NAV2_OBSTACLE_MODE=radar NAV2_VISION_OBSTACLES=1 ./run.sh start

# 手绘静态地图 + 视觉障碍检测
NAV2_ENABLED=1 NAV2_OBSTACLE_MODE=map NAV2_VISION_OBSTACLES=1 ./run.sh start

# 静态地图 + 毫米波 + 视觉障碍检测
NAV2_ENABLED=1 NAV2_OBSTACLE_MODE=both NAV2_VISION_OBSTACLES=1 ./run.sh start
```

启动后可先强停，再在网页勾选或取消“启用视觉障碍检测（参与导航避障）”，无需重启。网页选择仅对本次运行生效；“前方疑似障碍预览”只控制图像显示，不开启导航视觉避障。若终端已导出 `NAV2_VISION_OBSTACLES=1`，省略变量会继承该值，应在所选命令中显式设置 `NAV2_VISION_OBSTACLES=0` 才能关闭。

**不使用 Nav2，使用原跟随模式：**

```bash
NAV2_ENABLED=0 ./run.sh start
```

网页避障地图显示当前障碍来源，显示的代价地图包含所选图层。切换模式需要重启，不支持行驶中切换。雷达模式和叠加模式仍需启用毫米波；地图模式下毫米波不参与 Nav2 障碍判断，但网页独立的雷达测距开关仍可影响人物测距。

地图默认为 `nav2/maps/corridor.yaml`，可通过 `NAV2_MAP_FILE` 指定其它地图，但当前起点对齐固定为本走廊的设定。启动前将小车 base_link 放在最下排三块完整砖的中间砖中心（地图 x=1.2、y=0.3），车头朝上。底盘里程计必须从零开始；程序发布固定 `map → odom`：平移 (1.2,0.3)，旋转 +90°。不要同时运行 AMCL、SLAM 或其它发布同一变换的节点。当前仅靠轮式里程计维持位置，漂移不自动修正；每次重启重新对齐起点。

静态地图两侧墙、两端开放，未描述图外环境；滚动代价地图的图外区域不应视为已验证通行区域。先保持强停测试路径。仅地图模式无法检测临时障碍物，人物跟随仍需有效视觉测量。叠加模式保留雷达障碍，因此不会掩盖雷达误检。

启动后打开 http://192.168.31.214:8890/ 并刷新页面，确认“障碍来源”与选择一致。保持强停，选择当前人物 ID，再点击“停车预览路径”；雷达或叠加模式需先启用雷达。

常用管理命令：

```bash
./run.sh status
./run.sh logs nav2
./run.sh stop
```

每次启动都需带上 `NAV2_ENABLED=1` 和所选 `NAV2_OBSTACLE_MODE`；不指定障碍模式默认使用雷达，不启用 Nav2 时仍走原来的跟随模式。


脚本会检查依赖，启用 Ranger 的 `odom → base_link` TF，管理 Nav2 生命周期，再启动视觉控制。Nav2 激活失败不会启动视觉控制。启用状态随本次启动生效，重启时也需带 `NAV2_ENABLED=1`；不带时保留原来的 PID 跟随。

页面保持强制停止状态，雷达或叠加模式先启用现有毫米波雷达（或启动外部驱动），确认上述 TF 和轮廓，再解除强停、开始跟随。雷达点云超过 0.6 s、里程计 TF 超过 0.5 s、Nav2 速度超过 0.3 s 或视觉目标超时，自动跟随输出零速度。异步接受的旧导航目标也会取消。网页模式栏和 `/api/status` 会显示 Nav2 状态及错误。`NAV2_PARAMS=/绝对路径/params.yaml` 可使用自定义配置。

## 适用范围与验证

默认雷达模式是无预建地图、基于局部观测的绕行方案；地图及叠加模式使用手绘静态地图。当前均不使用 AMCL 或 SLAM。毫米波点云稀疏且视场有限，未检测到回波不能证明空间可通行；这里将未观测栅格作为自由空间，才能在无地图条件下规划。默认启用点云射线清障，漏检可能清除障碍；没有被射线扫过的旧障碍可能残留并阻止规划。应先在隔离场地低速检查雷达静态障碍检测、代价地图及路径；不能据此承诺全方位防碰撞。目标人物自身也会保留在障碍地图中，不会从点云里删除。

离线回归覆盖目标几何、跟随距离、目标更新边界、速度超时、传感器失效和强停后晚到的 action 响应；尚未完成 Nav2 运行时与实车绕行验证。首次实车验证需确认目标丢失停车、雷达断流停车、强停，以及正面障碍的左右绕行行为。

参考：[Nav2 Humble 参数](https://github.com/ros-navigation/navigation2/blob/humble/nav2_bringup/params/nav2_params.yaml)。

## 启动错误：RecoveryNode 未识别

Humble 会初始化单目标和多目标两个导航器。启动文件现在分别指定 `follow.xml` 和 `follow_through_poses.xml`，并加载两种规划动作插件，避免回退到依赖恢复节点的系统默认多目标行为树。当前不启用自动旋转、倒车等恢复行为，规划或跟随失败时任务结束。

修改后按上述启动步骤停止旧服务，再以所选模式启动。页面启动后保持强停，雷达或叠加模式启用雷达；代价地图在接收到有效点云前仍会提示 observation buffer 超时，这与行为树加载失败是不同问题。

### Nav2 自动跟随的视觉时效

Nav2 接入单独使用 1.2 秒的目标测量有效期（按原图采集时间计算），发送目标、速度放行和页面诊断使用同一阈值，避免沿用 0.6 秒阈值导致反复取消。Nav2 输出另限幅为线速度 ±0.15 m/s、角速度 ±0.4 rad/s；页面设置可进一步降低上限。普通视觉跟随仍使用原来的超时规则，停车预览仍为 2 秒。目标消失、距离缺失或超时仍停车，雷达、TF 和导航速度的新鲜度检查保持不变。该调整需重启服务生效，不能修正测距错误或保证规划成功。

### 导航目标防抖

仅在 Nav2 接入中对 odom 目标进行确认：连续 3 次测量的位置两两相距不超过 0.35 米、时间跨度至少 0.2 秒，才采用平均位置；相邻测量间隔超过 1.2 秒则重新确认。单帧跳变不替换正在执行的目标。已执行目标偏移超过 0.5 米且距上次发送至少 2 秒，才取消并重新确认新目标。强停、目标消失、进入跟随距离或传感器失效仍沿用停车逻辑，并清除防抖历史。停车预览保持原有单次规划行为。此功能减少目标抖动引起的任务切换，不会冻结 Nav2 根据障碍地图进行的正常重规划，也不能消除超时造成的取消。

导航实际停止或取消时，接入层会记录第一次触发原因，重复停车检查不会覆盖它或持续刷日志。避障地图区域显示“最近一次导航停止”及距今时间；详细记录位于 `data/runtime/control.log`，搜索 `Nav2 停止/取消`（接入层运行在控制进程，因此不写入 nav2.log）。可区分目标丢失、测量超时、用户/配置重置、稳定目标更新以及雷达/TF 等异常。历史停止原因不代表当前仍有该故障。

### 人物短暂超时的停车等待

Nav2 模式下，人物数据超过 1.2 秒仍立即输出零速度，但在测量年龄不超过 2.0 秒时短暂保留导航任务，最多额外等待 0.8 秒。恢复到 1.2 秒以内后，使用新的 Nav2 速度继续；等待期间清除速度缓存，不沿用暂停前指令。超过 2.0 秒仍取消，截止时间按原始测量时间计算，重复检查不会延长。目标丢失、距离缺失、强停及雷达/TF 异常仍取消。该机制减少短暂超时造成的任务重启，不修复视觉计算延迟，也不能消除规划失败；普通跟随与停车预览规则不变。

### 网页地图、车位与预计路线

网页“地图与导航路线”区域优先显示 `/map` 静态底图，并叠加局部代价地图；没有静态地图时使用原滚动障碍地图。静态底图按地图方向朝上显示。蓝色箭头表示 `odom → base_link` 给出的当前位置与朝向，蓝框为车身，绿色实线为导航规划路线，青色虚线为停车预览路线。全部图层先对齐到 odom，再统一绘制；静态地图不会因只发布一次而在 3 秒后过期。实时车位和导航路径仍保留过期检查，避免把旧数据当作当前状态。

需要重启服务并刷新网页。车位是里程计估计，不是新增的绝对定位；规划路线需要先请求停车预览或启动导航，不会仅因加载地图自动生成。

## 网页添加阻挡区与膨胀范围

默认局部、全局代价地图的 `inflation_radius` 均由 0.8 米调整为 **0.45 米**，`cost_scaling_factor` 保持 3.0，车身轮廓和 `footprint_padding=0.05` 不变。紫色代价区域因此缩小，仍会保留车身所需间距。若启动时指定了自定义 `NAV2_PARAMS`，请检查该文件中的半径设置。

以 `map` 或 `both` 模式启动后，网页“地图与导航路线”下方提供阻挡区编辑：

1. 保持网页强制停止，等待静态地图出现。
2. 点击“绘制阻挡区”，在地图上用鼠标或手机手指拖出矩形。
3. 检查虚线框位置，点击“应用阻挡区”。黑色矩形会合并到 Nav2 使用的静态地图中，而不只是页面装饰。
4. 等待代价地图更新，再重新点击“停车预览路径”，检查路线是否绕开新增区域。
5. “取消框选”放弃未应用的矩形；“撤销上一块”删除最后一个新增区域；“清空新增区域”删除全部网页新增区域，原地图墙体保持不变。

新增矩形按地图栅格对齐，当前地图为每格 0.05 米，最多 200 个。编辑时后端也检查强停状态；雷达单独模式不开放此功能。应用后旧停车预览会清除，不会自动开始运动。

保存位置为 `data/nav2_map_edits/<底图指纹>.json`，与原始 PGM/YAML 分开。地图内容、尺寸或原点变化会使用独立的编辑记录；同一底图重启后自动恢复。Nav2 启动时由 `nav2_map_publisher.py` 读取 `/map` 并发布合成地图 `/visual_car/edited_map`，两个代价地图的静态层订阅后者。网页保存后通知该节点重新加载；运行故障可在 `data/runtime/nav2.log` 中查询。没有新增阻挡区时合成地图与原图一致。叠加模式仍会保留雷达障碍。

代码更新后需要停止并重新启动服务，再刷新网页。此功能未替代定位或雷达检测，不会修正人物测距、视觉超时或里程计漂移。


### 自由画笔（鼠标／手机手指）

在地图或叠加模式保持强停，选择“自由画笔”和笔宽，点击“绘制阻挡区”后按住拖动画线。选择“矩形”可继续使用原矩形工具。笔宽为 1、3、5 个地图栅格，当前 0.05 米分辨率对应 5、15、25 厘米。连续移动会自动补齐中间笔迹。每笔绘画完成后点击“应用阻挡区”，再画下一笔；“撤销上一块”可整笔撤销，“取消框选”放弃未应用笔迹。自由画笔只标记涂过的区域，闭合线不会自动填满内部。新增笔迹与矩形统一保存、参与规划并支持重启恢复，旧矩形记录继续兼容。

这是对现有底图添加障碍的工具，并非 SLAM 或自动测量；地图比例和实际障碍位置仍需核对。当前不支持在网页改变地图尺寸、擦除原始墙体或重设定位。更新后重启服务并刷新网页。

## 独立禁入区相机预览（停车对齐）

地图旁新增“启用禁入区相机预览（停车）”。地图／叠加模式下保持强停，勾选后显示独立相机窗口；窄屏下排列在地图下方。仅将已应用的网页手绘禁入区域边界投影成淡红色墙面，不改变原相机画面、检测结果或导航地图。取消勾选停止请求；约每秒更新一次，图片独立缩放到最多 960 像素宽。

可设置相机高度、向下俯角和虚拟墙高度。默认分别为 0.5 米、0 度、0.8 米，属于待核对的显示参数；平面安装位置及偏航沿用 Nav2 相机安装参数，横滚暂按 0。需在停车状态核对地图起点、实际安装参数和显示位置。普通跟随和原相机功能不依赖此接口。

这不是新增的障碍检测或精确增强现实定位。相机画面和里程计未做严格同帧同步，因此当前只开放强停预览，解除强停后暂停，TF 或图像缺失时显示原因。使用当前相机标定文件投影，不支持任意更换镜头后的未标定画面。改动需重启服务、刷新页面生效。

## 固定路线：第一阶段停车校验

地图／叠加模式下保持强停，点击“选取路线终点”，在地图空地点击，再点击“预览选点路线”。不需要选定人物 ID。后端验证地图版本、边界及目标栅格；最终由 Nav2 判断路线是否可行。显示的是停车规划预览，不发送导航执行动作。地图编辑后应重新选点；规划成功不表示已确认执行路线。

可勾选“前方疑似障碍预览（待校验）”。独立窗口只读使用已有深度结果及同帧相机图像，不改变原相机、跟踪和控制流程。按填写的相机高度、向下俯角及深度比例，筛选相机前方约 0.15～3 米、左右各 0.6 米、估计离地 0.12～1.8 米的连通区域，以橙色显示候选区域和估计前向距离。未做物体类别识别，不覆盖低矮、悬空、透明物体或视野外障碍；这些范围相对于相机而非经过确认的底盘扫掠空间。

默认深度比例 1 尚未校验，相机横滚假设为 0。先在停车状态把已知距离的物体放入画面，核对标注、距离与安装参数。图像年龄超过 1.2 秒会拒绝预览；无候选区域不代表通道安全。当前没有固定路线执行或“检测到障碍自动停车”的控制接入，下一阶段需在完成现场校验后实现，原有人物丢失停车规则不变。

## 可选视觉障碍层（实验功能，默认关闭）

现在可将相机深度估计的疑似障碍加入 Nav2 局部、全局代价地图，与手绘禁入区一起参与规划。启动命令统一见[所有启动项指令](#startup-commands)，选择对应的“视觉障碍检测启动时开启”命令。

也可与 `both` 或 `radar` 模式组合。省略 `NAV2_VISION_OBSTACLES=1` 则关闭，保持原有行为。网页显示视觉障碍层是否启用、数据年龄、候选点数量和异常；原“前方疑似障碍预览”开关仍只管显示，不会开启或关闭控制保护。

安装参数通过启动环境变量设置：`NAV2_VISION_HEIGHT`（米，默认 0.5）、`NAV2_VISION_PITCH`（向下俯角，度，默认 0）、`NAV2_VISION_SCALE`（深度比例，默认 1）。平面安装参数沿用 `NAV2_CAMERA_X/Y/YAW`，横滚暂按 0。网页预览输入不会修改这些控制参数。必须先停车对照实物核对距离和位置，不能把默认参数当作准确标定。

接入层只读已有深度结果，不改变原人物跟踪或相机推理。按图像时间查找底盘 TF，在相机前方 0.1～4 米、左右各 2 米、估计离地 0.1～1.8 米范围内筛选连通候选区域。每个区域至少包含 6 个采样像素，按前向距离的第 10 百分位选取最近的一个区域，转换为 odom 栅格，通过 `/visual_car/vision_costmap` 发布。每次有效新帧替换视觉候选，不再保留旧候选两秒。连通区域不等同于物体类别，相连的多个物体可能成为一个区域，目标人物也可能被选中；独立橙色预览窗口仍显示其自身范围内的候选。

地图及叠加模式下，视觉栅格同时合入 `/visual_car/edited_map` 中的原地图墙体和手绘阻挡区，静态层显式启用最大代价合并，避免视觉自由栅格覆盖墙体。墙体按栅格面积转换，保留旋转坐标下的薄墙；未收到静态地图时拒绝发布视觉栅格并保持导航停止。仅雷达模式不等待静态地图。这些修改需重启服务生效。

有效像素不足、源深度超过 1.2 秒或 TF 失败时禁止 Nav2 输出并取消任务。底盘前方 0.7 米以内且左右各 0.4 米通道内出现候选时立即停止导航；更远的障碍交给规划器及局部控制器决定绕行，无可行路径则失败停止。该检查只保护 Nav2 自动速度，手动控制维持原逻辑。近距障碍消失、数据恢复后，开启着的人物跟随可能重新规划；如需保持停车请使用强停。

这不是经过验证的安全防碰撞功能：单目尺度误差、地面筛选、透明/低矮物体、视野盲区和安装误差均可能造成漏检或误检。不能承诺任意障碍必停。小地图代价区域是估计结果。此次仅把视觉层接入已有 Nav2 导航，固定选点仍为停车预览，未新增固定路线执行按钮，也未允许目标遮挡后沿旧路径继续走。


## 单地图模式的四周禁区

`NAV2_OBSTACLE_MODE=map` 自动启用独立边界层 `/visual_car/map_boundary`：在原地图外侧紧贴四条边添加一格宽、代价 100 的连续禁区，封闭四条边（包括原来开放的两端）。原地图文件、内部空间和起点不变；仅独立边界栅格宽高各增加两格、原点沿地图轴各向外移一格，正确处理旋转。当前边线宽 5 厘米，紫色膨胀区另行计算。局部和全局代价地图均在视觉层之前合入边界；最后的视觉层同时保留静态墙体和边界，随后计算膨胀；网页代价图仍裁剪到原地图范围，图外红边可能不显示，向内的膨胀区域仍显示。无需重新绘制，清除手绘区域不会移除边界。`radar` 和 `both` 模式不启用此边界。

重启后先保持强停，确认四周红色边界和小车位置，再计算停车预览路径；地图内无路可走时应规划失败，不能再从地图两端绕到外侧。车辆起始位置须与地图设置一致；此约束基于里程计定位，不能修正定位漂移，也不限制原手动控制。边界附近可能因车身轮廓和安全间距而无法规划，不能以缩小车身轮廓解决。


视觉层在地图及叠加模式下先按静态地图范围过滤候选，再选择地图内最近的有效连通区域，地图外候选不写入视觉障碍栅格。网页的 Nav2 代价叠加也裁剪到静态地图边缘，隐藏图外膨胀区域。近距停车仍检查全部有效候选，不因显示裁剪忽略车前危险。若障碍深度、高度或连通面积不满足筛选条件，仍可能没有标记；此功能不是物体类别识别。


地图模式启动先由 `nav2/map_startup.py` 在 45 秒期限内配置、激活地图，并确认原图、编辑地图和所需边界图已发布，然后启动导航生命周期管理器。状态切换响应丢失时查询实际状态，不重复发送同一切换；失败则结束本次 Nav2 启动，记录缺失图层。此处理避免地图服务响应丢失无限阻塞后续启动，不代表已修复底层 DDS 通信异常。


虚拟墙相机窗口按变化生成停车快照：首次勾选、保存/撤销/清除手绘区域、调整投影参数或车位累计变化至少 1 厘米/1 度时更新。静止且墙体未变时保留旧快照，不再每秒请求图像；背景人物变化也不会刷新。解除强停或位姿失效时隐藏，重新强停且数据有效后更新。未保存的绘制草稿不生成虚拟墙。请求失败可重新勾选重试。

“前方疑似障碍预览”勾选框仅开关独立橙色相机预览，不执行路线，也不启停导航视觉障碍层；该层仍由 `NAV2_VISION_OBSTACLES=1` 开启。“选取终点”及“预览选点路线”是另一组停车规划功能。


视觉障碍合并顺序：静态层 → 边界层（单地图模式）→ 视觉合成层 → 膨胀层。视觉合成层包含地图内最近有效候选、原墙体、手绘阻挡区及单地图模式的四周边界，避免最后再叠加只有边界的地图而丢失视觉障碍。需重启 Nav2 和视觉服务；候选仍取决于单目深度及安装参数，不能凭候选数量确认实物标注正确。

停车路径规划失败、超时或返回空路径时，地图下方显示红色“无有效路径”及失败原因。重新计算、清除或成功获得路径后撤销提示；尚未规划不等同于规划失败。


## 以所选人物为目标执行导航

人物自动跟随已接入 NavigateToPose，和手动选点停车预览是两条独立流程。启用 Nav2 后，选择画面中可见的人物 ID，在运动控制区启用自动跟随并解除强停；仅选择 ID、检测到人物或点击停车预览不会启动小车。

接入层使用所选人物的同帧距离和方位生成 odom 导航目标，终点位于人物前方的跟随距离处，而不是人物脚下；远目标分段推进，单次目标最远 3 米。通过连续 3 帧的位置稳定检查后发送目标，Nav2 自动规划并执行。人物位置稳定移动超过阈值时更新目标；无可行路径不能执行。人物丢失、距离缺失、传感器异常或强停时停车，短暂数据过期期间也不输出运动速度。

测试地图及视觉避障：使用[所有启动项指令](#startup-commands)中的“手绘静态地图 + 视觉障碍检测”。先确认人物 ID、距离、车位与地图一致，再启用跟随；若不动，查看控制状态和 Nav2 错误，不需要点击“预览选点路线”来执行人物跟随。


## 网页切换视觉障碍检测

**不带 `NAV2_VISION_OBSTACLES=1` 时，视觉障碍检测默认关闭。** 完整启动命令统一见[所有启动项指令](#startup-commands)。

地图旁“启用视觉障碍检测（参与导航避障）”可在强停状态切换，同时更新局部和全局视觉图层。关闭后不再处理视觉候选，导航不再使用该层，静态墙体及禁区保留；开启后等待新的有效深度数据。切换不解除强停、不启动跟随。“前方疑似障碍预览”仍仅控制独立图像显示。

更新代码后需重启一次加载可切换图层；此后无需重启即可勾选。`NAV2_VISION_OBSTACLES=1` 设置启动默认开启，不填写则默认关闭；网页选择仅对本次运行生效。切换失败时保持强停，重新切换成功或重启后再使用。


### 视觉障碍黄色虚拟墙

开启“启用视觉障碍检测”后，在强停状态可勾选其下方“显示视觉障碍黄色虚拟墙”。在原红色虚拟墙相机窗口中，将实际选中的视觉候选栅格叠加为半透明黄色墙，不新增相机窗口。红墙和黄墙可独立勾选，也可同时显示。黄色墙使用导航视觉层的相机高度及俯角，示意墙高 0.8 米，不代表物体真实高度。候选区域或车位变化才重新生成；数据过期、候选消失、关闭视觉检测或解除强停时隐藏。该勾选只控制显示，不改变障碍筛选或运动控制。更新后重启服务并刷新网页。


地图接口超时排查：已修复新增视觉定时器反向获取引擎锁与导航锁的死锁风险；先复制引擎记录并释放引擎锁，再进入导航临界区。网页请求失败时仅保留带“缓存底图”标识的静态背景，隐藏车位、路径、动态障碍及虚拟墙，禁用地图操作；连接恢复后自动恢复实时显示。若旧进程已死锁，需停车后重启服务加载修复。


红黄墙合并预览修复：清除手绘区域仅改变红墙，黄色墙仍来自视觉候选。勾选黄墙后不会因一次视觉状态采样暂时失效而静默改成只请求红墙；数据过期时隐藏并提示，恢复后自动重试。预览成功并与当前状态一致后才记录缓存版本，失败或被丢弃的响应不再阻止后续刷新。真实无候选时仍不画黄色墙，不沿用失效候选。


## 执行停车选点终点导航

保持强停，在地图选取空地终点并点击“预览选点路线”。预览成功后 30 秒内可点击“开始行驶到终点（解除强停）”：该按钮明确解除强停并启动自动终点导航，不需要开启人物跟随。Nav2 根据最新地图重新规划，实际路线可能与预览不同。地图修改、其他预览覆盖或旧任务未结束时拒绝执行，需重新预览。

固定终点导航不依赖人物可见性；仍检查定位及所启用传感器的新鲜度并限制速度。手动模式、跟随模式切换及强停会取消该任务；“停止终点导航”也会锁存强停。到达或失败后不自动重复发送目标。代码接入使用原有唯一速度发布通道，没有第二个底盘速度发布者。需重启服务并刷新网页加载，首次在空旷区域低速核对，尚未完成实车验证。


### 导航生命周期响应超时

新增 `startup_watchdog.py` 只读查询 controller/planner/navigator 的生命周期状态，保留原 Nav2 管理器及运行时 bond 健康检查。25 秒无状态推进或总等待超过 65 秒时中止本次启动并记录各节点状态（1 未配置、2 未激活、3 已激活）。不会盲目重复发送配置请求，也不会将查询失败视为激活成功。退出时给生命周期管理器有限的 TERM/KILL 等待时间，避免新启动继续遗留卡住的管理器；此前已经残留的进程仍需按原清理步骤处理。这是启动失败处理改进，不能消除底层 ROS 2/DDS 响应丢失。


### 终点导航的短暂视觉断流

固定终点执行时，视觉障碍数据年龄超过 1.2 秒立即输出零速度，但在最后一次成功发布数据的源时间起 2 秒内保留任务；没有延长可运动数据有效期。新有效视觉数据恢复后丢弃等待期间速度，收到新的控制器指令才继续。数据年龄超过 2 秒、TF/雷达异常、近距障碍或无效深度仍取消；取消后不自动重启。无障碍的有效帧照常更新时效，不会因为候选数为零而停车。此修改处理短暂断流，不等于解决上游深度推理延迟。


### 原地转向的进展检查

控制器改用本机已安装的 `nav2_controller::PoseProgressChecker`：相对基准位置移动 0.15 米或朝向变化 0.15 弧度（约 8.6°）即计为进展。10 秒内两者均未达到仍停止，避免真正卡住时一直执行。此前只统计平移，低速掉头时即使持续旋转也可能被误判为无进展。此修改不提高速度、不开放倒车；实车只倾斜一点的底盘响应问题仍需结合角速度和里程计验证。使用自定义 `NAV2_PARAMS` 时也需同步这三个进展参数。停车后重启服务加载。

Nav2 实际输出角速度上限调整为 ±0.4 rad/s（约 23°/秒），线速度仍为 ±0.15 m/s。规划器角速度上限为 0.5 rad/s，最终由接入层和网页速度设置共同限幅；网页上限若低于 0.4 rad/s，仍取较低值。只提高上限，不强制每次按最大角速度旋转，不绕过碰撞、超时或进展检查。停车后重启加载。


### 减少转向时路径更新和角度微调

两个导航行为树的全局重规划频率由 2 Hz 调整为 0.5 Hz（约每 2 秒一次）；局部控制仍按 20 Hz 工作，实时碰撞检查保留。DWB 的 `PathAlign.scale` 从 24 降为 12，降低路径对齐在轨迹评分中的权重；这不是固定的沿途角度放行阈值。终点 `yaw_goal_tolerance` 从 0.5 调整为 0.7 rad（约 40°），只放宽抵达后的朝向要求，位置容差仍 0.15 米。全局绕行路径响应可能比以前慢，局部无安全轨迹时仍停车。未更改车身、禁区或传感器有效期；停车后重启加载，需实车核对是否改善微调。


### 固定目标沿用已规划路线（当前行为）

取消行驶中的定时全局重规划，两个行为树使用顺序执行：先计算一次路径，再持续执行该路径。相同导航任务内，普通视觉候选刷新不会重新下发全局路径。本节取代上文每 2 秒重规划的说明。局部控制仍会调整速度和转向以沿原路径行驶，因此不能保证方向盘完全不微调。

实时碰撞检查、0.7 米近距视觉停车条件、定位及传感器超时检查继续生效。原路径无法安全通行或控制器判定无进展时，任务失败停车，不自动绕行重规划；需重新预览并开始导航。检测不到障碍不能证明安全。人物跟随目标稳定移动超过既有阈值时仍会取消旧任务并生成新目标路径；固定选点模式没有此目标更新。修改后停车重启服务生效。

网页地图缩放条旁新增“显示紫色缓冲区（仅显示）”复选框，默认勾选，取消后仅隐藏紫色代价区域；红色障碍、墙体、路线和车位保持显示。此项不修改 Nav2 膨胀半径或碰撞检查，不发送后端控制请求；刷新页面恢复默认勾选。


### 实际关闭或调整导航缓冲区

地图缩放处新增“启用导航缓冲区（实际参与规划）”及 0～1.5 米半径滑块。先强停，调整后点击“应用缓冲设置”；后端同时修改局部和全局的 `inflation.enabled`、`inflation.inflation_radius`，读取确认一致后反馈成功。取消勾选并应用会真实禁用膨胀层，不只是隐藏颜色。障碍物本体、地图边界和车身轮廓碰撞检查仍有效；车身安全边距不随滑块改变。零半径与关闭都不会删除障碍物。

设置会清除旧预览，需重新规划；失败或响应超时则禁止新增导航，保持强停重新应用成功或重启后恢复。选择只对本次运行有效，重启使用 YAML 默认值；首次更新需重启服务并刷新网页。“显示紫色缓冲区”仍是独立显示开关，观察实际半径时请勾选。关闭缓冲后路线可能更贴近障碍。


膨胀设置接口已改用独立 ROS 参数客户端和执行线程，避免主单线程执行器等待运动锁时无法处理参数响应。写入响应超时后不重复写入，而是读取两张代价地图实际值；仅两者与请求一致才反馈成功并解除设置未确认拦截。查询也失败或值不一致时仍保持拦截。需重启视觉服务加载此修复。


### 按车身宽度和转弯空间规划

默认全局规划器改为本机已安装的 `nav2_smac_planner/SmacPlannerHybrid`，预览和实际导航均使用同一 `GridBased` 插件。搜索包含朝向，按 costmap 中的矩形 footprint 检查碰撞：车身 0.494 × 0.364 米，四周 padding 0.05 米，直行所需宽度至少约 0.464 米；实际还受地图分辨率、转角和障碍形状影响。不能仅凭中心线能穿过就认定车身能通过。关闭紫色膨胀层也不取消 footprint 检查。

暂采用仅前进 DUBIN 搜索、0.4 米最小转弯半径、72 个朝向、原始 5 厘米栅格，并关闭路径平滑；该转弯半径是待实测参数，不是底盘测得值。窄处可能返回无路，而不应提供穿过车身障碍的中心线。局部控制仍保留车身碰撞检查，感知与定位误差仍可能影响实际安全距离；不能保证实物未被检测时避碰。更新需停车重启并重新预览旧终点。自定义 NAV2_PARAMS 不会自动替换其中的规划器。


路径穿越手绘禁区的补充修复：边界发布器改订阅编辑后的地图，完整保留内部墙体和手绘障碍，而非用全自由内部覆盖。停车预览返回前，使用实时带 padding 的车身轮廓逐段插值，检查多边形内部与边缘是否占据静态墙、手绘禁区或图外区域；失败则拒绝预览，不允许执行该预览。此复核独立于可关闭的紫色膨胀；实际行驶仍依赖 Nav2 最新代价地图和局部碰撞检查。重启后重新预览，旧预览不再使用。
