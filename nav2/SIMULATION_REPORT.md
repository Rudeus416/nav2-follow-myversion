# Nav2 离线时序与冲突模拟报告

日期：2026-09-29。对应用户指令：“先模拟监测有没有冲突或者延时等问题”。

**R36 修复前结论：已有回归通过，但新增模拟复现了暂停策略冲突，以及会影响行驶连续性的处理顺序和锁占用问题。R35 的性能优化尚不能保证连续行驶。** 本轮只新增模拟脚本、结果与报告；本轮开始时的生产 Python/C++/配置文件、原控制/相机/启动脚本/前端均经校验保持不变。没有启动底盘、相机、推理模型或真实 ROS 节点/动作。

## R37 修复与复测（2026-09-29）

对应用户指令：“修复这些模拟时出现的问题”。下面第 1～5 节保留 R36 的修复前证据；当前实现已修复第 1～4 项代码冲突，第 5 项真实慢源数据仍必须按时效保护停车。

| 模拟条件 | R36 修复前 | R37 修复后 |
|---|---|---|
| 已验证绕行，保留近距提示，源年龄 1.3 秒 | 速度入口暂停，视觉入口直接取消 | 两种入口顺序均零速暂停、保留任务；源年龄 2.01 秒才取消 |
| 引擎锁被占用 350 毫秒，邮箱已有新帧 | 完整 tick 等待约 352 毫秒 | tick 约 8.3 毫秒完成，首次邮箱等待记录为 0.000 秒 |
| 发布函数被阻塞 350 毫秒 | 速度出口等待约 351 毫秒，指令过期归零 | 速度出口约 0.30 毫秒返回，未等待发布，指令仍有效 |
| 可选语义工作阻塞 300 毫秒 | 0.95 秒旧的深度再等 0.30 秒而过期 | 独立 owner 仍阻塞时，深度 tick 约 14.0 毫秒已完成；新帧被采用 |

这些是本次离线延迟注入样本，不是实时性上界或实车测量。完整回归 **418 项通过（17.670 秒）**，另外 **14 条持续时间线**及语义/暂停/锁占用断言通过。[R37 结构化结果](tests/simulation_results_r37_20260929.json) 与 [R36 原始结果](tests/simulation_results_20260929.json) 分别保留。

修改位置与逻辑：

- `vision_layer.py`：`VisionStale` 与速度链路统一调用零速暂停。TF、深度几何、候选筛选、构图及 ROS 发布不再整个占着 `nav.lock`。输入先取快照，提交时复核任务代次、导航配置代次、流/模型配置和实际源时间。危险全量点云先提交并触发停车；清除危险/恢复有效数据则等当前地图发布完成后整批提交。
- `vision_epoch.py`：在 Nav2 内为现有引擎实例的 `configure` 安装可还原适配；开始配置先使快照失效，成功结束才发布一致版本。读取邮箱不等融合引擎锁；旧融合缓冲仅非阻塞补读。原 `control.py` 未改。配置异常、重叠配置及关闭中的晚结果不能重新授权。
- `semantic_dispatch.py`：最新引用投递、结果/状态缓存；启动、缩图、收包和关闭由另一串行 owner 调用现有自有 `SemanticWorker`。仍只接受同配置、同流、同帧语义，不将旧掩膜套到新图。
- `vision_toggle.py`、`vision_calibration.py`：停车切换先失效正在计算的任务；快速 off/on 也立即清语义代次。真实地图编辑、校准或配置变化重置安全确认帧计数；不能把旧配置的两帧安全确认带进新配置。相同地图的重复发布不打断视觉计算。
- `semantic_obstacles.py`：清理未启动/部分初始化的进程与队列；退出未完成时保留所有权并重试，防止旧进程未退出又启动第二个。工作线程关闭后也拒绝晚到视觉提交。

补充的竞态回归覆盖计算期间用户取消、配置切换、校准、发布期间失效、关闭期间晚结果、新图发布前不恢复无障碍证据，以及真实近距危险在发布前即停车。原视觉层开关参数服务仍在强停状态下等待响应，本次没有将该停车配置接口改成行驶时调用。

发布调用已经进入后无法撤回单条 ROS 消息；因此配置失效会立即清除本地可行驶证据，下一代无障碍证据必须等其地图发布返回后才恢复。这里没有新增外部代价地图的接收确认协议，原 Nav2 订阅仍是异步的。

**仍存限制：** 到达时已经 0.90 秒旧、每 0.80 秒才更新的合成源依旧有 69.5% 零速输出；这证明输入预算不满足 1.2 秒要求，不代表仍有本轮锁冲突。没有改原模型或延长旧证据寿命；持续源年龄超过 2 秒仍取消。未重启服务或发送实车运动；原控制、相机、启动脚本与原前端六个文件 SHA-256 均与本轮开始一致，自有根目录 `nav2_follow.py` 也未改。本轮变化全在 `nav2/`。

## R36 修复前记录

## 模拟范围与证据

- 原有 **375 项离线回归通过，18.412 秒**。覆盖人物历史点、固定路径、取消、真实障碍、掉帧恢复、地图编辑、车身检查及新缓存。
- 新增 **14 组持续时序场景**：手动选点/人物固定段各 7 组，每组模拟 12 秒，速度出口 50 Hz，输入控制指令 20 Hz、每 3 秒切换转向。调用真实自有视觉几何、导航状态机及加速限幅，深度为空场景合成值，TF 和动作服务使用假对象。
- 另做前置语义阶段延迟、已验证绕行暂停冲突，以及真实线程的正常/引擎锁/发布锁占用探针。
- [结构化结果](tests/simulation_results_20260929.json) 保留输入条件和实际输出。注入的延迟是测试条件，**不是现场实际耗时**。指令速度积分不是实测里程；没有模拟底盘动力学、CAN、真实 GPU 推理、图像识别质量，或运行外部 DWB 控制器/进度检测器。

## 1. 绕行状态下，两个入口对同一过期帧作出不同决定

位置：[vision_layer.py](vision_layer.py) 的 `_tick_locked()` 异常分支，约第 498 行；对照 [nav2_follow.py](../nav2_follow.py) 的 `velocity()` / `pause_for_vision()`。

复现条件：人物固定段已通过绕行复核，`task.permits_near=True`，保留近距障碍提示，源数据年龄 **1.3 秒**。

1. 速度出口遇到 `VisionStale`：输出零速，但 `enabled=True`、固定路线和绕行任务保留。
2. 视觉更新入口处理同一帧：由于 `vision_error` 非空，没有进入短暂等待；直接清空视觉证据、取消路线。

这是真实状态机的入口冲突。它会让某些绕行场景绕过“源年龄到 2 秒才持续超时取消”的既有规则；不表示近距障碍应该放行。后续应统一旧证据的暂停分类，保持零速，并保留新鲜真实危险、TF 故障、人工取消的终止保护。

## 2. 视觉计算和发布长时间占用速度门控的锁

位置：[vision_layer.py](vision_layer.py) 的 `tick()` 在约第 337 行取得 `nav.lock`，整个 `_tick_locked()` 在其中执行，包括几何、栅格构建和 `publisher.publish()`；`Nav2Follower.velocity()` 使用同一锁。

真实线程探针中，给本地假发布回调注入 **350 毫秒**阻塞：

- 速度出口等待约 **351 毫秒**，相当于约 17.6 个 20 毫秒控制周期。
- 解锁时，控制指令年龄约 **359 毫秒**，超过 0.3 秒门槛，输出零速。
- 此时视觉年龄仅约 **459 毫秒**，任务仍启用，视觉无错误。

因此即使视觉数据本身新鲜，长临界区也能拖慢速度门控，并产生指令过期停车。没有证明实车发布一定耗时 350 毫秒，但代码允许这种互相阻塞。后续应在锁外计算/发布，用短临界区提交完整快照，并检查任务代次、地图/配置版本和实际源时间；不能仅移除锁而引入旧计算覆盖新状态。

## 3. 深度直通缓存仍会先等待原引擎锁

位置：[vision_layer.py](vision_layer.py) 的 `tick()` 约第 288 行先读 `engine.lock`，第 296 行才取 `DepthMailbox.latest()`。

注入 **350 毫秒**引擎锁占用时，邮箱里已经有结果并已通知，完整 `tick()` 仍等待到锁释放；本轮实测 `mailbox_wait` 约 **352 毫秒**。单独读取邮箱很快，不能证明完整导航消费已不依赖融合锁。本例速度出口没有直接等待引擎锁。

后续应给最新结果消费建立不等待融合重计算的配置/视频流快照边界，保留配置校验；不能跳过版本检查或将旧源时间改为接收时间。

## 4. 前置语义接入能把新鲜深度拖到过期

位置：[vision_layer.py](vision_layer.py) 的 `tick()`，先选择深度帧，再调用 `semantic.update()`，之后才进入安全几何。

虚拟时间探针：读取时年龄 **0.95 秒**的帧，在可选语义接入阶段耗时 **0.30 秒**后变成 **1.25 秒**，未被采纳为新安全证据，速度输出零。YOLO 模型运行在独立进程，但其启动、提交缩图、结果收取等调用仍排在本轮深度安全检查之前。注入场景只证明耦合，并不证明实车该阶段目前固定消耗 0.30 秒。

后续应使可选语义任务不阻塞关键深度处理；仍须同帧配对，不能将旧掩膜套到新图像。新数据在处理期间到达时，需要有明确的最新结果选择与版本验证边界。

## 5. 持续慢帧与加速平滑叠加，仍会造成停走

手动选点与人物固定段在以下合成场景表现一致：

| 到达时已有的帧龄 | 到达间隔 | 12 秒模拟结果 |
|---|---|---|
| 0.35 秒 | 0.20 秒 | 零速占比 0%，任务持续 |
| 0.60 秒 | 0.50 秒 | 零速占比 0%，任务持续 |
| 0.90 秒 | 0.80 秒 | **零速占比 69.5%**；指令速度积分仅 0.143 米，任务暂未取消 |
| 1.05 秒 | 1.00 秒 | 约 **0.96 秒后取消**；下一个结果到来前，上次有效数据的源年龄已超过 2 秒 |
| 0.35 秒，正常 5 Hz | 中途短缺帧 0.8 秒 | 停车后恢复，任务保留 |
| 0.35 秒，正常 5 Hz | 中途断流 3 秒 | 持续超时取消；后续帧不能擅自复活路线 |

其中周期性停走的关键是：**数据到达时已经消耗了有效期，等待下一帧时年龄还在增加。** 0.90 + 0.80 ≈ 1.70 秒，跨越 1.2 秒零速门槛；每次停车重置加速过渡，恢复后又从低速起步。这个模拟没有证明进度检测器已触发，但指令积分很小，存在进一步触发无进展停车的风险。

所有这些场景中，实际输出记录均未使用超过 1.2 秒的证据放行；人工取消后也没有自动恢复。没有发现本轮模拟中的死锁；发现的是可复现等待、停走和入口决策冲突，不能据此宣称整个系统绝无死锁。
